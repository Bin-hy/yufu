# 前端业务异常与反馈交互 Spec

状态：已获用户批准，已完成实现及前端范围验收；实际证据与验证边界见 [verification.md](verification.md)。

## 背景

当前身份业务已返回稳定的错误分类和请求标识，包括负责人约束、最后管理员保护、审批过期及提交结果未知。前端请求层仅翻译部分浏览器校验错误及无效输入，其他结构化错误容易退化为通用 HTTP 错误，用户无法理解失败原因或下一步操作。

项目已有页面错误状态、表单错误、Toast、普通确认框和危险操作确认框，应在既有交互基础上完善异常反馈。当前工作区有其他未提交功能，本次保留并兼容这些改动。

## 目标

- 用户明确知道什么操作失败、可公开的原因及下一步操作。
- 依据失败发生的上下文选择提示位置，避免同一次失败重复提示和连续弹窗。
- 失败不丢失输入、不误报成功、不诱导重复执行可能已成功的写操作。

## 方案比较

| 方案 | 收益 | 局限 |
| --- | --- | --- |
| 统一错误语义并按场景反馈（推荐） | 覆盖已有业务分类，复用组件，兼顾原因、恢复和干扰程度 | 需协调请求层、页面和反馈组件 |
| 只补充错误文案 | 改动较小，快速改善可读性 | 无法解决重复提示、弹窗关闭及恢复操作问题 |
| 所有失败统一弹窗 | 错误醒目 | 加载和批量请求会频繁打断操作，表单错误脱离上下文 |

## 功能需求

- F1：统一解析已有业务异常，保留分类、状态及可用请求标识；对已有身份业务分类提供中文原因和下一步建议，包含权限不足、资源不存在、冲突、链接过期或已使用、负责人约束、最后管理员保护、审批过期、禁止自审、登录或授权要求、依赖不可用、超时、容量不足和提交结果未知。兼容既有结构化响应与安全的旧响应，不将 HTTP 客户端默认英文报错作为主要业务提示。
- F2：区分网络不可达、请求超时、服务错误、HTML 代理误配和主动取消；取消及会话切换产生的过期请求不提示失败。未知异常提供可理解的兜底文案和可用请求标识。
- F3：表单提交失败在原表单或原对话框中持续展示原因，保留用户输入并恢复提交能力；已有字段级校验继续定位对应字段。只有服务端实际提供可定位字段时才补充字段错误，不凭通用无效输入推测具体字段。
- F4：读取失败使用页面内错误状态和重新加载；刷新失败保留旧结果并明确标注。普通短反馈使用 Toast，同一次请求的本地提示与全局提示不重复；同一原因的并发全局反馈合并或抑制，避免堆积。
- F5：需要用户决策的阻断问题使用合适的对话框，例如重新登录、数据版本冲突以及提交结果未知。说明原因、受影响操作和可用的下一步；仅提供当前页面确实支持的恢复动作。数据冲突不直接重放旧提交，提交结果未知先引导核对现状，不提供盲目再次提交。
- F6：危险操作提交前继续说明对象和影响；确认框承载提交时，提交失败保持确认框打开并展示原因，执行中防止重复提交。已采用先确认、再执行的页面须在原上下文清晰反馈执行失败，不产生无上下文的连续弹窗。
- F7：登录凭据错误维持不暴露账户是否存在的提示；会话过期统一处理并防止多个受保护请求同时触发多个重新登录提示。会话相关反馈与现有会话清理及跳转机制兼容。

## 非功能需求

- N1：保持现有权限、CSRF、会话刷新和并发版本检查规则；不为改善文案放宽业务约束。
- N2：不向用户展示数据库详情、堆栈、令牌、密码或内部依赖原文；不将未知对象直接转换成字符串展示，也不将返回的 HTML 作为内容渲染。
- N3：反馈支持键盘操作、清晰的可访问名称、恰当的朗读提示及焦点恢复。重要且需要处理的错误不依赖短暂自动消失提示传达。
- N4：优先复用现有反馈组件，统一中文文案和操作词，不引入第二套 UI 框架。

## 不做的事

不重构完整业务流程，不新增通知中心、外部告警渠道或全站国际化，不修改标准 OIDC/OAuth 协议错误契约，不自动重试写操作。本期优先使用后端已有公开分类；仅当实现确认存在无法表达的业务原因时，再提出必要的后端补充，不承诺将所有通用无效输入细化为字段错误。

## 验收标准

- AC1（F1）：模拟负责人约束、最后管理员保护、禁止自审、过期审批、失效链接和权限不足，页面分别显示明确且不同的中文原因及建议；可用请求标识可供排查。
- AC2（F2）：模拟断网、超时、服务异常、未知响应和 HTML 响应，展示对应安全文案；取消和过期会话请求不产生错误提示。
- AC3（F3）：表单提交失败后原内容仍在、错误持续可见且允许修正后提交；已有字段校验位置不退化，不将通用错误错误归因到某个字段。
- AC4（F4）：首次加载失败可重新加载，刷新失败保留并标注旧数据；单次失败不会同时出现重复的本地错误和全局 Toast，并发同类全局错误不堆积。
- AC5（F5）：版本冲突要求先刷新核对；提交结果未知明确说明可能已生效并引导核对，操作过程中不自动重复写入。
- AC6（F6）：危险操作先显示对象及影响；确认框内执行失败保持打开并显示原因，执行期间重复点击不会产生第二次提交。
- AC7（F7）：错误凭据不区分账户存在与否；并发会话过期仅产生一次清晰的恢复流程，既有会话清理及跳转仍正常。
- AC8（N1—N4）：完成前端类型检查、lint、构建和相关单元回归；对登录失败、表单失败、列表重试和阻断弹窗执行组件或浏览器行为验证，检查键盘、焦点及脱敏行为。未执行项和环境限制如实记录。
