# 前端业务异常与反馈交互 Checklist

状态：用户已批准，已完成前端范围验收；证据、执行方式及未覆盖范围见 [verification.md](verification.md)。

每项通过运行代码或观察用户可见行为验证。已勾选条目仅表示 verification.md 所列前端测试与模拟接口范围通过，不代表真实后端或全部浏览器验收。

## 错误原因与建议（AC1、AC2）

- [x] C01：负责人约束提示先转交负责人，最后管理员保护提示需保留有效管理员，自审限制提示由其他有权人员审批；三种错误可明确区分。（验证：业务分类测试及管理员/审批页面组件测试，注入对应错误响应并检查可见文案。）
- [x] C02：权限不足、资源不存在、数据冲突、审批过期、链接过期及链接已使用各有对应原因和建议，不退回通用 HTTP 英文错误。（验证：逐类注入已知业务响应，检查解析输出及代表页面显示。）
- [x] C03：已有身份业务与浏览器认证公开分类均有中文提示；通用无效输入要求检查表单，不虚构具体错误字段。（验证：表驱动测试覆盖全部现有公开错误码及既有 CSRF 分类。）
- [x] C04：有合法请求标识时显示一次，可用来排查；响应体缺少合法标识时支持响应头回退，非法或超长标识不进入提示。（验证：正常、缺失、非法、超长和响应体/头冲突用例。）
- [x] C05：断网、读取超时、限流、依赖故障、服务异常和 API 返回 HTML 时展示对应原因及安全建议。（验证：Axios adapter 注入不同失败，检查实际反馈。）
- [x] C06：未知对象、未知错误码、空响应及非 Error 异常显示安全兜底，不出现 `[object Object]`、原始 HTML、数据库详情、堆栈或测试秘密。（验证：注入带敏感标记的响应，断言反馈文本及渲染 DOM 不含标记。）
- [x] C07：主动取消、页面切换取消和旧会话晚到响应不出现错误 Toast、错误弹窗或错误表单提示；仍活动的操作不会因取消一直处于忙碌状态。（验证：延迟响应后取消或切换会话，检查可见反馈、按钮和请求次数。）

## 表单与读取反馈（AC3、AC4）

- [x] C08：登录、账户资料和应用编辑的代表性提交失败后，普通输入仍在，错误在原上下文持续可见；修正后能够再次提交。（验证：挂载实际表单页面，填写、注入失败、修改并再次提交，检查值与按钮状态；不要求保留会话清理时应删除的秘密。）
- [x] C09：现有字段级校验仍显示在对应字段；只有服务端确实给出字段信息时才定位字段，通用失败不随意归因。（验证：应用登记字段校验回归及通用 invalid_input 场景。）
- [x] C10：首次加载失败显示失败和重新加载入口，点击后成功数据替代错误；不把失败显示成空列表。（验证：列表页面第一次读取失败、第二次成功的交互测试。）
- [x] C11：刷新失败保留上次结果，并明确显示旧结果和刷新失败；重试成功后清除错误。（验证：先成功读取，再注入刷新失败及后续成功，检查原数据、提示和重试行为。）
- [x] C12：提交已成功但随后的读取刷新失败时，提示刷新失败，不声称提交失败，也不引导重复写入。（验证：实际业务页面写入成功、后续读取失败，检查显示和写入次数。）
- [x] C13：由本地表单、列表或确认框承接的失败不额外产生全局 Toast；没有本地承接的全局请求仍可见失败原因。（验证：分别触发 local/global 请求，检查页面与 Toast 数量。）

## Toast 与打断程度（AC4、AC8）

- [x] C14：短时间并发同类全局异常只显示一条提醒，即使异常对象或请求标识不同；不同原因仍可区分。（验证：并发请求和虚拟时钟测试，检查实际提示数量及文案。）
- [x] C15：后续独立重试失败仍能获得提醒；默认错误/警告展示 6 秒，显式设置 0 不自动消失，可见 Toast 不超过 4 条。（验证：虚拟时钟前进、主动关闭和超过数量上限，检查可见状态。）
- [x] C16：会话重置后旧 Toast 消失且计时器清理，旧提示不会在新会话重新出现。（验证：展示多条提示后重置会话并推进时钟，检查提示和计时器状态。）
- [x] C17：普通输入与读取失败不强制弹窗，已有编辑框或确认框不会被第二个错误弹窗覆盖；需要处理的重要错误有持续可见的承载位置。（验证：检查表单、列表、确认框及阻断操作的交互场景与活动对话框数量。）

## 冲突、未知结果与危险操作（AC5、AC6）

- [x] C18：数据版本冲突和审批过期先要求核对最新状态，恢复按钮只执行页面支持的读取或导航，不直接重放旧提交。（验证：注入冲突后点击恢复入口，检查请求方法、写入次数和提示。）
- [x] C19：重新读取与核对不会静默覆盖尚未提交的普通输入；确需放弃草稿时沿用现有放弃确认。（验证：修改表单后制造冲突并恢复，检查草稿或放弃确认行为。）
- [x] C20：服务端 commit_uncertain 或已发出写入后的网络/超时异常明确说明结果可能已生效；不显示盲目重新提交的主要操作。（验证：分别注入服务端未知结果和传输失败，检查文案与按钮。）
- [x] C21：创建结果未知后，多次点击核对仅执行读取，不重复 POST；读取找到已创建对象时恢复结果，仍无法核对时保持未知。（验证：模拟写入结果未知及后续读取，断言写入仅一次，核对次数与显示状态正确。）
- [x] C22：危险操作确认时显示真实对象及影响；执行中重复点击不会产生第二次写入，忙碌时不能关闭确认框。（验证：实际危险操作页面及确认组件测试，延迟写响应后重复点击、Escape 和关闭按钮。）
- [x] C23：确认框内执行失败时保持打开，展示具体原因并解除忙碌；可安全重试的已知失败允许再次确认，成功才结束确认。（验证：注入约束错误后检查弹窗仍在，再模拟可安全执行成功的路径。）
- [x] C24：确认框执行结果未知时，不允许再次执行原写入；用户可取消或按实际支持的方式返回页面核对。会话重置或卸载能够结束等待中的确认流程。（验证：结果未知、取消、重置和卸载组件测试，检查写入次数、弹窗状态及等待 Promise 结算。）

## 登录与会话恢复（AC7）

- [x] C25：错误密码与不存在账户显示相同的凭据错误提示，登录校验失败不被误认为已登录会话过期。（验证：实际登录表单分别返回对应拒绝响应，检查用户可见文案和跳转行为。）
- [x] C26：多个受保护请求同时返回 401，仅执行一次清晰的过期恢复流程，先清理旧会话，再进入登录页显示原因；旧响应不恢复旧身份。（验证：并发 401 与延迟旧响应的会话集成测试，检查清理、跳转次数及身份状态。）
- [x] C27：首次匿名访问与主动退出不显示会话异常；后续新会话再次真实过期仍可收到提示。（验证：匿名访问、退出、重新登录和再次过期序列测试。）
- [x] C28：会话恢复提示不保存密码、令牌、一次性链接或旧账户敏感表单数据；登录后的业务身份仍从现有会话接口恢复。（验证：使用测试秘密触发过期，检查页面状态及本地/会话存储，结合既有身份恢复测试。）

## 集成、可访问性与兼容（AC8、N1—N4）

- [x] C29：原 Axios 异常的状态、响应及取消分类仍可被调用方读取；CSRF 证明、认证刷新、并发控制和会话隔离既有测试继续通过。（验证：请求及身份回归测试；不修改后端权限或标准协议契约。）
- [x] C30：错误提示具备恰当的 alert/status 语义；恢复按钮有可理解名称，支持 Tab/Enter，关闭对话框后焦点回到合理位置。（验证：组件语义断言及浏览器键盘交互；纯 DOM 断言不视为屏幕阅读器实机验证。）
- [x] C31：没有实际恢复回调时不出现无效按钮；恢复中防止重复操作；原有 Dialog、AlertDialog 和视觉样式保持一致。（验证：反馈组件与实际页面的交互测试和视觉检查。）

## 完整用户流程

以下场景须以实际页面执行从用户操作到结果显示的完整交互。可使用受控请求响应模拟失败；应记录使用的页面、异常注入、操作和实际结果。组件流程可验证前端行为，但不标记为真实服务端到端通过。

- [x] E01：登录页输入凭据 → 返回凭据错误 → 原表单显示统一安全原因 → 修改输入 → 登录成功进入工作台。（验证：实际登录页面组件流程；可用浏览器环境中补充页面操作记录。覆盖 C08、C25。）
- [x] E02：管理员点击停用账户 → 核对对象与影响 → 提交返回最后管理员保护 → 原确认框显示原因且无额外 Toast → 取消后返回原位置。（验证：实际账户页面组件或浏览器流程。覆盖 C01、C13、C22、C23、C30。）
- [x] E03：列表首次加载失败 → 点击重新加载成功 → 再次刷新失败 → 保留并标注旧数据 → 重试成功恢复。（验证：实际列表页面组件或浏览器流程。覆盖 C10、C11。）
- [x] E04：编辑应用并提交 → 返回版本冲突或审批过期 → 看到具体原因与核对操作 → 核对最新状态，处理草稿 → 未经再次明确提交不产生写请求。（验证：实际应用详情页面流程。覆盖 C02、C18、C19。）
- [x] E05：创建提交可能已完成但返回结果未知 → 提示先核对 → 连续核对仅发送读取 → 找到现有对象并展示结果，始终仅一次创建请求。（验证：实际创建页面流程，记录读写次数。覆盖 C20、C21。）
- [x] E06：工作台多个请求同时遭遇会话过期 → 一次清理和跳转 → 登录页显示原因 → 新登录后旧请求不能覆盖当前身份。（验证：真实路由与会话组件集成或浏览器流程。覆盖 C26—C28。）
