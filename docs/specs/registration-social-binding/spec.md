# 邀请注册时同步绑定第三方身份 Spec

> 状态：已实现，验证通过（2026-11-27）
> 范围：仅“新建账户”的企业邀请注册；已有账户接受邀请和密码找回不在本次范围
> 分支基线：`ui/compact-interface`（当前工作分支）

## 背景

Yufu 目前支持两类身份入口：

- 账户密码登录，以及通过企业邀请创建新账户；
- 已登录用户在账户中心绑定 GitHub、QQ、微信等第三方身份。

邀请注册的当前流程是：

1. 管理员签发邀请，接收人打开邀请链接或输入邀请码；
2. 注册页设置用户名、显示名称和密码；
3. 提交后创建 Yufu 账户，但新账户返回“需要登录”；
4. 用户再用刚设置的密码登录；
5. 如需第三方登录，再进入账户中心单独绑定。

这导致初次注册和第三方绑定被拆成两个独立动作。用户希望：在邀请注册时，如果服务端已启用对应的第三方登录方式，注册页直接展示可选绑定入口；用户选择后，创建账户、登录并完成第三方绑定，不需要第二次登录或再进账户中心。

此外，管理员签发邀请后只看到一次性回执，刷新页面即失去上下文，无法查看之前签发过哪些邀请、是否已被接受或撤销。邀请表目前只保存 secret 的 SHA-256 摘要，**原始邀请链接/邀请码无法恢复**；因此需要提供邀请记录列表（状态与元数据），并允许对待用邀请撤销、对需要继续使用的邀请重新签发。

## 当前实现与差距

| 能力 | 当前状态 | 差距 |
|---|---|---|
| 邀请注册 | `POST /api/v1/identity/invitations/accept` 创建账户；新账户返回 `requires_login=true`，不建立中心会话 | 无法在注册后直接继续第三方绑定 |
| 第三方绑定 | `/api/v1/identity/external/{provider}/bind/start` 要求已有 SSO Cookie | 注册完成前不能绑定 |
| Provider 可用性 | `GET /api/v1/identity/external/providers` 只返回已启用且配置完整的 Provider | 可直接复用，无需新增配置接口 |
| 邀请与 OIDC 衔接 | 邀请动作可携带 `flow_id`，接受邀请后可继续原授权流程 | 同步绑定后需要保留该续接能力 |
| 邀请记录 | 签发后只有一次性回执；无历史列表接口 | 增加邀请历史、状态、撤销与重新签发 |
| 账户中心绑定 | 已支持 GitHub/QQ/微信绑定、解绑与最后凭据保护 | 本次不改变其语义 |

关键约束：

- 邀请注册仍必须设置 Yufu 密码，不允许无密码社交注册。
- 第三方身份只是额外绑定，不能替代 Yufu 账户和 `sub`。
- 已有账户接受邀请时，不展示“同时绑定”；仍使用账户中心绑定。
- 不自动合并账号，不按邮箱/昵称匹配。
- 不改变下游 OIDC 接入方式。

## 目标

- 新建账户的邀请注册页根据服务端 Provider catalog，展示已启用且配置完整的 GitHub/QQ/微信绑定入口。
- 用户可以选择一个 Provider，完成“创建账户 → 自动建立中心会话 → 第三方授权 → 绑定”的一条连续流程，无需再次输入密码。
- 用户也可以选择“仅创建账户”；新账户同样自动建立中心会话，但不进入第三方授权。
- 第三方授权取消或失败时，账户仍然有效并保持登录；若源自 OIDC 登录则继续原授权流程，否则进入账户中心并提示可补绑。
- 管理员可以在刷新后查看邀请记录列表，包括用途、人员类型、状态、创建人/时间、到期时间、接受人；可撤销待用邀请，并可重新签发新链接。
- 不改变已有账户的邀请接受、账户中心绑定/解绑和下游 OIDC 行为。

## 成功标准

- 注册页只展示服务端已启用的 Provider；未配置或禁用时不显示。
- 选择 Provider 后，注册页无需二次登录即可进入对应平台授权；成功后账户与第三方身份同时存在。
- 取消/失败不会丢失已创建账户，也不会伪造绑定成功。
- 若邀请携带 OIDC `flow_id`，绑定完成后继续原授权事务；失败时按约定继续或回到账户中心。
- 刷新邀请页面后仍可看到历史邀请及状态；原始 secret 不会从列表恢复。
- 已有账户接受邀请时看不到同步绑定入口。
- 现有 OIDC、注册、绑定、解绑和会话测试无回归。

## 功能需求

### 注册同步绑定

- **F1 注册页展示可绑定 Provider。** 新建账户的邀请注册页在表单下方展示服务端当前已启用且配置完整的 GitHub/QQ/微信入口。入口为单选，默认不选；未选择等同于“仅创建账户”。Provider 目录为空或读取失败时隐藏该区域，不影响注册。
- **F2 已有账户不展示同步绑定。** 已有账户接受邀请、普通登录、账户中心绑定和其他登录入口保持现有界面与行为，不出现“注册时同步绑定”入口。
- **F3 提交注册时携带可选 Provider。** 新建账户提交时除邀请凭据、用户名、显示名称和密码外，可携带一个已展示的 Provider 标识；密码仍为必填，不接受无密码社交注册。服务端重新校验邀请状态、有效期、目标账户和 Provider 可用性，不信任前端展示结果。
- **F4 创建账户后自动建立会话。** 新建账户接受邀请成功后，服务端在同一业务操作中完成账户创建、邀请消费和中心会话建立，并按正常登录语义下发会话 Cookie。用户不需要再次输入密码；会话 TTL、CSRF、浏览器绑定和撤销语义与密码登录一致。
- **F5 账户与会话原子性。** 账户创建、邀请消费和会话建立必须一起成功或一起失败。任一步骤失败时不得留下“账户已创建但无法登录”或“邀请已消费但账户不存在”的中间状态；失败响应应允许用户重试或联系管理员。
- **F6 选择 Provider 后继续绑定。** 会话建立后，若用户选择了 Provider，前端立即使用该会话发起对应 Provider 的绑定授权，不得再次要求输入 Yufu 密码。一次注册最多选择一个 Provider。
- **F7 绑定前再次校验 Provider。** 发起绑定时服务端再次确认 Provider 仍启用且配置完整、该账户尚未绑定同 Provider、第三方身份未被其他账户占用。校验失败不得阻断已完成的注册和登录，应保留账户与会话并提示可稍后补绑。
- **F8 绑定成功。** 第三方授权成功并完成绑定后，账户与第三方身份同时存在并记录审计。若本次注册来自 OIDC 授权请求，继续原 OIDC 流程；否则进入账户中心身份页并展示绑定成功状态。
- **F9 绑定取消或失败。** 用户在第三方页面取消授权，或授权、回调、绑定任一步失败时，已创建的账户和中心会话保持有效，邀请保持已消费，不得回滚账户，也不得伪造绑定成功。若本次注册来自 OIDC 授权请求，按已登录用户继续原 OIDC 流程，允许稍后补绑；否则进入账户中心身份页并提示绑定失败及可重试。
- **F10 OIDC 续接。** 邀请动作携带 OIDC 流程时，无论是否选择 Provider，注册完成后最终都回到原 OIDC 授权流程；同步绑定不得丢失、替换或提前消费该流程。无 OIDC 流程时进入账户中心。
- **F11 绑定内容边界。** 同步绑定只创建第三方身份映射，不修改 Yufu 用户名、`sub`、密码、人员类型或开发者资格；不按邮箱、昵称或 unionid 自动合并账户。

### 邀请记录与重新签发

- **F12 邀请历史列表。** 管理端提供邀请记录列表，刷新或重新进入页面后仍可查看历史签发记录。默认按创建时间倒序，展示用途、人员类型、开发者资格、目标账户（如有）、创建人、创建时间、到期时间、状态、接受人及接受时间、撤销时间。列表不得返回 secret、secret 摘要或其他可恢复旧链接的材料。
- **F13 邀请状态。** 每条记录派生一个状态：已接受、已撤销、已过期、待用。状态优先级为已接受 > 已撤销 > 已过期 > 待用；已接受记录不再因到期或撤销改变状态。
- **F14 筛选、搜索与分页。** 列表支持按状态、用途、人员类型筛选，支持按目标账户、接受人、创建人搜索，并支持分页加载。筛选和搜索条件变化后从第一页重新加载。
- **F15 撤销待用邀请。** 仅“待用”邀请可撤销。撤销需二次确认；成功后该邀请立即失效，其他并行邀请不受影响，并记录审计。已接受、已过期、已撤销记录不提供撤销操作。
- **F16 重新签发。** 任意历史记录可重新签发。重新签发创建一条新邀请记录，复制原记录的用途、目标账户、人员类型和开发者资格，使用新的随机 secret、新的摘要和当前邀请有效期；签发人为当前管理员。原记录保持不变。
- **F17 多链接并行。** 重新签发不撤销原邀请，也不使其他待用链接失效；同一用途、同一目标可以同时存在多条待用邀请。列表需能区分这些记录，管理员可分别撤销。
- **F18 新链接一次性展示。** 签发和重新签发成功后，新邀请链接只展示一次；列表只展示记录与状态，不提供“查看旧链接”。需要再次发送时只能重新签发。
- **F19 重新签发校验。** 重新签发前重新校验原记录和目标账户仍可签发。目标账户不存在、已停用或不符合资格时拒绝签发且不创建新记录；失败原因可被管理员理解。
- **F20 权限与审计。** 查看邀请列表沿用现有账户读取权限；撤销需要邀请撤销权限；签发和重新签发需要邀请签发权限。签发、接受、撤销、重新签发均记录操作者、邀请标识、结果和必要的关联标识；列表只读不记录逐次读取审计。

### 兼容与范围

- **F21 已有账户邀请不变。** 已有账户接受邀请仍要求当前会话，接受后继续现有 OIDC 逻辑，不出现 Provider 选择，也不改变人员类型或开发者资格校验。
- **F22 现有 OIDC 与绑定不变。** 下游 OIDC 客户端、账户中心绑定/解绑、最后凭据保护、密码登录和密码找回均保持现有行为；同步绑定只是复用既有绑定能力。
- **F23 失败可恢复。** 注册、绑定、列表加载、撤销和重新签发的失败均需给出明确提示，并保持页面可继续操作；不得出现空白页或静默失败。

## 非功能需求

- **N1 密钥与凭据保护。** 邀请 secret、第三方 token、Provider client secret 和内部摘要不得出现在列表响应、审计详情、日志、错误信息或页面可恢复内容中；新邀请链接只在签发/重新签发成功时返回一次。
- **N2 权限与请求防护。** 邀请列表、撤销、签发、重新签发均要求管理员身份与对应权限，并沿用现有 CSRF、浏览器绑定和会话校验；同步绑定只能作用于当前已登录账户，不能借注册流程提升权限或绑定到其他账户。
- **N3 服务端为准。** Provider 是否展示、是否可绑定、邀请是否有效、记录状态和权限均以服务端校验为准；前端隐藏或禁用不构成安全边界。已禁用或配置不完整的 Provider 即使被伪造请求也不得发起授权。
- **N4 原子性与一致性。** 新建账户的账户创建、邀请消费和会话建立必须原子完成；邀请接受、撤销、重新签发在并发下必须产生可解释的单一结果，不得出现同一邀请被接受两次、已接受记录被撤销、或账户存在但邀请未消费等不一致状态。
- **N5 并发与重复提交。** 同一邀请的并发接受只能成功一次；绑定重复回调按幂等处理；撤销与接受并发时以先获得锁的操作为准，后到请求返回明确冲突或已消费结果。重新签发进行中应禁用重复触发，避免误触生成多条记录。
- **N6 失败隔离。** Provider 目录读取失败、第三方授权取消/超时/错误、绑定冲突、列表读取失败均不得破坏已创建的账户和中心会话，也不得使邀请回到待用状态；失败后页面必须可继续操作。
- **N7 性能。** 不包含第三方网络的本地处理：注册提交、撤销、重新签发 p95 不超过 2 秒；Provider 目录读取和邀请列表首屏 p95 不超过 800 毫秒；分页加载单页 p95 不超过 800 毫秒。第三方绑定耗时受外部平台影响，不纳入该指标。
- **N8 数据量控制。** 邀请列表必须服务端分页，默认每页不超过 50 条，不得一次性加载全部历史；筛选、搜索和排序在服务端完成，数据量增长后仍保持稳定响应。
- **N9 可观测性。** 签发、接受、撤销、重新签发、同步绑定请求、绑定成功和绑定失败均产生结构化审计或日志，包含请求标识、操作者、邀请/账户/Provider 关联标识和结果；不得记录 secret、摘要、token 或完整第三方资料。
- **N10 审计一致性。** 签发、接受、撤销和重新签发等邀请写操作的审计与业务写入保持同一事务语义，审计写入失败时不得静默成功；第三方授权失败等发生在外部边界的事件允许采用尽力而为审计，但必须产生可检索的结构化日志。列表读取为只读操作，不要求逐次审计。
- **N11 隐私最小化。** 列表只展示管理所需的最小账户信息；第三方头像、邮箱、openid/unionid 等不进入邀请列表。搜索与筛选结果不得泄露无权限账户的额外信息。
- **N12 兼容性。** 已有邀请链接、已有账户接受邀请、普通登录、账户中心绑定/解绑、密码找回和下游 OIDC 流程保持可用；新增字段必须可选，旧客户端忽略新增字段时不得报错。
- **N13 会话语义一致。** 自动建立的会话与密码登录使用相同的有效期、CSRF、浏览器绑定、停用账户处理和撤销机制；账户被停用后，同步绑定流程不得继续或恢复会话。
- **N14 时间与状态一致。** 邀请状态由服务端时钟计算，到期边界为“当前时间大于等于到期时间即过期”；前端展示服务端返回的状态，不依赖客户端时钟自行推断，避免时区或时钟偏差导致误操作。
- **N15 可访问性与提示。** Provider 选择、邀请列表筛选、撤销和重新签发均支持键盘操作与明确焦点；状态不能只靠颜色区分；错误、成功和一次性链接展示需有可读文本与可被辅助技术识别的提示。
- **N16 响应式可用。** 注册页 Provider 区域、邀请列表及操作在窄屏下保持可用，关键状态和操作不被横向裁切；一次性链接提供复制能力，复制失败时可手动选择。
- **N17 OIDC 安全续接。** 同步绑定携带的 OIDC 流程标识必须与发起注册的浏览器绑定一致，只允许续接服务端已存在的流程；不得接受客户端任意跳转地址，绑定回调不得成为开放重定向。
- **N18 可测试性。** 账户/会话原子性、邀请并发接受、撤销与接受竞争、绑定取消/失败、OIDC 续接、列表筛选分页和重新签发多链接并行均需有自动化测试覆盖；测试不得依赖真实第三方平台。

## 不做的事

- **不改变已有账户接受邀请。** 已有账户仍按当前会话接受邀请并继续原 OIDC 流程，不出现 Provider 选择、不自动建立新会话、不改变人员类型或开发者资格校验。
- **不做无密码或纯社交注册。** Yufu 密码始终必填；第三方身份不能替代密码、用户名或中心账户，也不能作为 Yufu 的 `sub`。
- **不做账户自动合并。** 不按邮箱、昵称、手机号、openid 或 unionid 合并账户，不把第三方身份自动关联到疑似同一人。
- **不支持一次注册绑定多个 Provider。** 注册页最多选择一个 Provider；其他第三方身份仍由账户中心后续绑定。
- **不新增第三方平台。** 本次只复用 GitHub、QQ、微信开放平台网站应用扫码；不接入小程序、公众号网页授权、企业微信、钉钉、Apple 等其他入口。
- **不建设 Yufu 小程序或客户端登录协议。** 不新增 `wx.login`、`code2Session`、小程序专用接口、handoff/resume 或原生客户端扫码协议；下游小程序仍使用标准 OIDC。
- **不改变下游 OIDC 协议与声明。** 不新增 scope、claim、客户端配置或授权端点行为；同步绑定只影响 Yufu 自身的注册与绑定过程。
- **不改变账户中心绑定/解绑语义。** 不调整绑定列表、解绑确认、最后凭据保护或已绑定 Provider 的冲突规则；注册同步绑定复用现有能力。
- **不提供旧邀请链接恢复。** 邀请 secret 只存摘要，列表不展示、不导出、不找回旧链接；需要再次发送只能重新签发。
- **不自动撤销旧邀请。** 重新签发不吊销原邀请或其他待用链接，不强制“同一目标只能有一条有效邀请”；多链接并行是明确允许的行为。
- **不提供邀请编辑。** 已签发邀请的用途、目标账户、人员类型、开发者资格和到期时间不可修改；需要变更时撤销后重新签发。
- **不做批量邀请操作。** 不提供批量签发、批量撤销、批量重新签发、CSV 导入导出或邀请码批量生成。
- **不做邀请发送与提醒。** 不发送邮件、短信、IM 消息，不做到期提醒、接受提醒或自动重发；管理员自行复制新链接。
- **不做邀请统计报表。** 不新增接受率、转化率、渠道分析等报表；列表仅提供状态筛选和搜索。
- **不新增管理员角色。** 不设计新的权限模型；列表、撤销、签发和重新签发沿用现有邀请管理权限。
- **不改变邀请保留与清理策略。** 不新增自动清理过期邀请记录的任务；历史记录是否保留沿用现有数据保留策略。
- **不做跨浏览器或跨设备续接。** 注册、绑定和 OIDC 续接仍受现有浏览器绑定约束；不提供把流程转移到另一浏览器继续的能力。
- **不做第三方资料同步。** 不同步第三方头像、昵称变化、邮箱变化或好友关系；只保存绑定所需的最小标识。
- **不做注册页整体改版。** 不重构普通登录、已有账户邀请、账户中心或管理端其他页面；仅在新建账户注册页和邀请管理区域增加所需入口与列表。
- **不改变密码与找回流程。** 不调整密码强度策略、密码找回、会话有效期、记住用户名或“记住我”行为。

## 验收标准

### 注册同步绑定

- **AC1 Provider 展示。** 在服务端仅启用 GitHub 的测试环境中打开新建账户邀请：页面只出现 GitHub，不出现 QQ/微信；禁用 GitHub 后刷新，入口消失且注册仍可提交。
- **AC2 仅创建账户。** 不选择 Provider 提交有效邀请：账户创建成功、中心会话 Cookie 下发、`requires_login` 为 false；无需再次输入密码即可访问账户中心。
- **AC3 选择 Provider 注册。** 选择 GitHub 提交有效邀请：账户创建成功、中心会话建立、邀请被消费；随后自动进入 GitHub 授权地址，过程中没有第二次密码输入。
- **AC4 绑定成功。** 使用 fake GitHub Provider 完成回调：`identity_external_identity` 新增该用户与 GitHub 的映射；页面进入身份页或原 OIDC 流程，且不出现绑定失败提示。
- **AC5 绑定取消/失败。** 在第三方页面取消或让 fake Provider 返回错误：账户仍存在且可访问账户中心，邀请保持已消费，第三方映射不存在；若邀请携带 `flow_id`，继续原 OIDC 流程；否则进入身份页并显示可重试提示。
- **AC6 注册原子性。** 通过测试触发器让会话或审计写入失败：邀请仍为待用、账户不存在、响应失败；修复故障后可重试成功，不出现半完成账户。
- **AC7 并发接受。** 两个请求同时接受同一邀请：最多一个成功；另一个返回已消费/冲突；数据库中该邀请只被消费一次。
- **AC8 OIDC 安全。** 使用不匹配的浏览器或伪造 `flow_id` 发起同步绑定续接：请求被拒绝，不产生开放重定向；合法 `flow_id` 在绑定成功和失败后都能继续到原授权流程。
- **AC9 已有账户不变。** 已登录账户打开邀请：不显示 Provider 区域，接受后按原逻辑继续；账户中心绑定/解绑、密码登录、密码找回测试无回归。

### 邀请记录

- **AC10 历史可见。** 签发邀请后刷新或重新进入管理页：列表仍显示该记录；不选择 Provider 的记录同样可见；空数据时显示空状态。
- **AC11 状态正确。** 分别构造待用、已接受、已撤销、已过期记录：列表状态分别为待用、已接受、已撤销、已过期；已接受记录即使同时到期或撤销仍显示已接受。
- **AC12 筛选与分页。** 按状态、用途、人员类型筛选及按目标/接受人/创建人搜索，返回结果与条件一致；构造超过一页数据时使用下一页游标加载，单页不超过 50 条，不重复不遗漏。
- **AC13 撤销。** 撤销一条待用邀请：该链接立即不可用，其他并行待用链接仍可用；已接受/已过期/已撤销记录无撤销入口或请求被拒绝；审计新增撤销事件。
- **AC14 重新签发。** 对已接受、已撤销、已过期、待用记录分别重新签发：每次创建新记录并返回新链接，原记录字段和状态不变，原待用链接仍可用；新链接可完成注册或资格接受，且只展示一次。
- **AC15 重新签发校验。** 目标账户已停用或不存在时重新签发：请求被拒绝且不创建新记录；重新签发的有效期使用当前配置，而不是原记录剩余时间。
- **AC16 多链接并行。** 对同一用途、同一目标连续重新签发两次：列表出现三条待用记录（含原记录），三条链接均可独立使用或被撤销，互不影响。
- **AC17 秘密保护。** 列表响应、审计详情、错误信息和日志中不出现邀请 secret、secret 摘要、Provider token 或 client secret；旧链接无法从任何管理接口恢复。
- **AC18 权限。** 无账户读取权限的管理员访问列表被拒绝；无签发权限不能重新签发；无撤销权限不能撤销；有对应权限的操作成功并记录操作者。
- **AC19 状态时间。** 将测试时钟推进到到期时间点：记录立即变为已过期；前端不因本地时区或时钟偏差显示错误状态。
- **AC20 审计。** 签发、接受、撤销、重新签发、同步绑定成功和失败均产生可检索记录；事件包含请求标识与邀请/账户/Provider 关联标识，且不含敏感材料。

### 界面与兼容

- **AC21 可访问性。** Provider 卡片、列表筛选、撤销和重新签发可用键盘完成；状态除颜色外有文本标识；错误、成功和一次性链接提示可被辅助技术读取。
- **AC22 响应式。** 在窄屏下注册页、邀请列表、撤销和重新签发操作可完成，关键状态和按钮不被裁切；一次性链接复制失败时可手动选择。
- **AC23 兼容性。** 旧版本签发的邀请链接仍可打开并完成原有流程；旧客户端忽略新增响应字段时仍能工作；下游 OIDC 客户端无需修改即可完成授权。
- **AC24 失败可恢复。** Provider 目录、列表、撤销、重新签发和绑定失败时，页面保留当前上下文并提供重试或返回路径，不出现空白页或静默失败。
