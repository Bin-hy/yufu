# 企业统一身份与受控应用接入 Spec

日期：2026-11-09，Asia/Shanghai。

状态：需求已于 2026-11-09 获用户确认；当前定义第一版行为和验收要求。

## 背景

项目定位已经确定：企业统一身份与单点登录平台，提供受控的应用接入和开发者自助管理能力，覆盖企业自研应用及获准接入的第三方应用。

现有项目已有账户、OAuth/OIDC、应用与客户端注册、凭据管理、刷新轮换、撤销、审计和管理界面。第一版应将这些能力组合为可使用的企业身份产品，让业务应用通过标准协议接入，减少各自维护注册、密码验证和登录界面的成本。

本轮核对发现：浏览器访问令牌按标签页保存，中心登录恢复仍受前端状态影响；应用、OAuth 客户端与安全绑定分开管理；账户企业准入、开发者资格、协作管理、上线审批和应用用户分配没有形成完整产品流程。已有撤销实现也不能直接证明第三方应用自己的会话已经退出。

## 目标与第一版边界

1. 一套部署服务一家企业，使用一个稳定的身份签发方。企业内部用户与获邀合作方共用账户体系，但分别获得明确权限。
2. 企业账户建立一次，在所有获准访问的应用中使用同一身份；中心会话有效时，同一浏览器访问另一个应用无需重复输入凭据。
3. 企业授权的开发者可以自行完成应用注册、开发环境测试、配置维护和上线申请。
4. 企业管理员掌握账户准入、开发者资格、生产应用批准、用户访问范围及身份信息授权。
5. 企业采购的第三方应用可以由管理员配置接入；供应商无需因此获得认证中心管理权限。需要供应商协作时，通过邀请和指定应用权限接入。
6. 两个独立参考应用能使用标准 OIDC 客户端完成登录、身份映射、会话管理和退出验证。

第一版提供用户账户中心、开发者控制台、企业管理控制台三个入口。同一人可具备多种资格；进入某个界面不自动增加其服务端权限。

### 交付方案选择

| 方案 | 收益 | 代价 | 本次选择 |
| --- | --- | --- | --- |
| 在现有项目形成统一身份、SSO 与受控自助接入闭环 | 复用现有能力，同时实现用户与开发者两侧的目标 | 需要补齐账户准入、应用生命周期和会话关联 | 推荐，作为本 Spec 的交付范围 |
| 先提供 SSO 和管理员配置应用，后续再补开发者自助接入 | 首次 SSO 验证范围较小 | 初期接入仍依赖管理员，不能完整交付已确定定位 | 作为开发顺序参考，不缩减最终验收范围 |
| 同时提供公开开发者注册和多企业应用分发 | 扩大外部接入范围 | 额外引入跨企业身份、公开准入与应用分发治理 | 留给后续产品阶段 |

## 角色与关键语义

| 概念 | 明确定义 |
| --- | --- |
| 企业管理员 | 管理账户、开发者资格、应用批准、访问分配和审计；管理权限不自动授予所有业务应用的用户访问权 |
| 企业用户 | 通过企业受控开户或邀请建立身份，只有被分配的应用才允许登录 |
| 合作方账户 | 企业邀请的外部人员账户；默认没有员工组成员资格、全企业人员查询权或业务应用访问权 |
| 开发者资格 | 创建应用和进入开发者控制台的资格；与既有业务角色、应用用户访问权分别管理 |
| 应用负责人／维护者 | 管理指定应用的人员；只能看到和操作所负责应用，负责人支持交接和增减维护者 |
| 应用访问分配 | 用户或用户组可以登录应用的企业授权；与开发者管理权、用户同意披露身份信息分别管理 |
| 中心会话 | 浏览器在身份中心完成认证后建立的会话，是跨应用复用认证的依据 |
| 应用会话 | 应用自己建立的登录状态，通过接入约定与中心会话关联；不是多个应用共用同一个访问令牌 |
| 开发／生产环境 | 同一应用的两个接入环境，拥有独立配置和凭据。开发环境成功不等于生产环境已获准使用 |

第一版的用户组为扁平成员集合，用于应用访问分配；不引入部门树、组织继承或跨企业租户。

## 功能需求

### F1：企业受控开户与账户生命周期

- 新部署默认关闭无邀请的公众自助注册。管理员可以创建账户或生成有有效期、只能成功使用一次的邀请链接。
- 邀请用于企业用户开户、合作方开户或为已有账户授予受邀资格。链接由管理员交付，第一版不依赖自动发信服务。
- 邀请所授予的人员类型和资格由管理员确定，接受邀请者不能自行提高权限；并发接受只能产生一次有效结果。已有账户必须认证后接受邀请，不能仅凭相同用户名合并身份。
- 用户从应用发起登录后可接受邀请并注册，完成后继续原应用的授权流程。原应用上下文与邀请应独立验证。
- 用户可以更新基本资料、凭现有密码修改密码。忘记密码时，由管理员签发一次性、限时的重置链接；重置不能由匿名用户直接发起并生效。
- 管理员可以停用和重新启用账户。停用、密码修改或重置会撤销该账户的中心和应用授权会话；重新启用不恢复已经撤销的凭据。
- 已有身份的稳定标识不因昵称、用户名、资格或访问分配变化而改变，注销后也不将同一身份标识转给另一人。

### F2：开发者资格与指定应用协作

- 管理员可以授予、撤销开发者资格，管理扁平用户组和成员。
- 开发者可创建应用；负责人可将已具有开发者资格的人员加入自己的应用、移除维护者、交接负责人。向尚无资格的外部人员发出邀请由管理员完成。
- 维护者只能管理明确分配给自己的应用；应用管理者不能借成员管理授予平台管理员或开发者资格。
- 每个应用必须保留一个启用的负责人。负责人停用或资格撤销前，管理员应完成交接或停用其应用，禁止遗留无人负责的生产应用。
- 合作方和普通开发者只能选择获准协作的人员、用户组或测试人员，不能由此浏览企业完整目录。

### F3：一次完成应用注册与环境配置

- 创建应用时选择企业自研或第三方接入，指定名称、说明、负责人和接入类型。第一版支持服务端 Web 应用与浏览器单页应用。
- 一次成功注册完成登录所需的应用、客户端、环境、身份签发和受众关联；开发者不需要手工补充数据库或后台安全绑定。
- 开发与生产使用独立客户端标识、回调配置和凭据。服务端客户端获得需要保密的凭据；浏览器单页客户端不发放客户端密钥。
- 开发环境可配置本机回调；生产使用经过批准的 HTTPS 回调。回调必须明确注册，不能使用任意跳转或通配符放宽匹配。
- 同一注册过程失败时不留下可用于登录的半成品；网络响应丢失后可核对已有结果，不能因重试产生重复有效客户端。
- 开发环境默认只允许负责人、维护者及管理员指定的测试用户登录。开发者不能利用测试环境扩大对生产人员身份信息的访问。

### F4：应用上线与配置变更审批

- 新应用生产环境依次经历开发准备、待审批、已启用；管理员可拒绝并给出原因，申请退回可修改状态。已启用应用可以停用和恢复。
- 审批内容包括生产回调、客户端类型、身份信息范围、受众、负责人、用户访问范围与退出能力。申请者不能批准自己的生产上线；具有管理员和开发者双重资格的人员也适用。
- 管理员直接配置第三方应用属于管理授权操作，须记录操作者及配置快照；无需给供应商创建开发者账户。
- 审批固定对应一份配置。审批期间发生敏感变更后，旧审批不能使新配置上线。
- 生产回调、受众、客户端类型、身份信息范围等敏感配置变化需要重新批准；旧的已批准配置可以继续服务，直到新配置批准并切换。普通显示名称和说明调整不扩大权限。
- 停用应用后，中心停止为其签发和刷新凭据，并撤销已有有效授权；恢复启用不恢复旧令牌。

### F5：用户和用户组访问分配

- 新应用默认不向企业全部用户开放。管理员可以为生产应用分配启用的用户或用户组，并可撤销分配。
- 判断是否允许登录时，必须同时满足账户启用、应用启用、有效访问分配和已批准环境配置；开发环境按 F3 的测试人员规则判断。
- 平台管理员、开发者、应用负责人身份都不能绕过用户访问分配。具有管理权不代表可以作为用户登录业务应用。
- 用户同意授权不能替代企业访问分配。没有被分配的用户不能在同意页自行获得访问权。
- 撤销用户分配或用户组成员关系后，中心拒绝相关应用的新登录与刷新，撤销相关已有授权，其他应用的分配不受影响。

### F6：跨应用 SSO 与授权流程恢复

- 未认证用户从应用进入中心登录页，认证后返回最初发起的应用。登录、邀请开户、密码重置后的返回流程应保留并重新验证原授权上下文。
- 同一浏览器已具有有效中心会话时，无论同一标签页、新标签页还是页面重新加载，访问另一个获准应用都不因缺少当前标签页访问令牌而重复要求密码。
- 中心会话恢复依据服务端可验证的会话状态，不依赖把中心访问令牌写入业务应用存储、共享给其他域或放入 URL。
- 并发访问两个应用和并发恢复会话不得误判为用户重放攻击，不能因一个正常请求使另一个应用反复退出；同时保留真正刷新重放的拒绝与撤销语义。
- 中心会话过期或被撤销时，停止自动登录并要求重新认证；已过期的前端状态不能充当有效会话。
- 支持明确要求重新认证及限制认证时间的 OIDC 行为；无交互请求在已有认证和授权充分时直接成功，否则返回标准交互错误，不显示登录或授权页面。
- 单次授权请求仅用于其已注册客户端和回调；授权码只能成功兑换一次，并校验防请求混淆、关联响应和 PKCE 的证据。

### F7：企业批准、用户同意与最小身份信息

- 企业自研应用可以由管理员按已批准身份范围设置预授权。已认证、已分配的用户无需重复确认基础身份披露。
- 第三方应用默认仍要求用户确认允许披露的身份信息；管理员可以明确预授权。任一方式都不能绕过 F5。
- 应用申请的新身份范围超出已批准内容时，不得因为既有同意记录而自动扩大披露；生产变更按 F4 处理。
- 每个接入环境的身份响应只面向该客户端，按批准范围返回真实可用的资料。未请求或未批准的信息不返回，缺少邮箱时不生成虚构邮箱或伪造验证状态。
- 同一企业用户在获准应用中具有稳定的身份签发方与主体标识组合。应用按照这组标识创建或关联业务资料，无需再次收集和验证用户密码。
- 中心登录与基础身份获取不要求用户先获得业务资源权限，不把全部业务角色和资源授权塞入每个登录响应。

### F8：接入凭据与配置管理

- 有权管理应用的人员可以查看接入配置并重置相应环境的客户端凭据；明文密钥仅在产生时展示一次，后续读取不返回旧明文。
- 凭据重置、客户端配置切换及应用停用有明确生效结果和审计；旧密钥立即不能再用于中心客户端认证，其他环境的密钥不受影响。
- 浏览器单页应用不能通过界面、旧管理接口或直接请求获得保密客户端能力。
- 创建者、维护者、管理员之间采用明确授权检查；只知道应用标识或修改请求中的所属人不能读取和管理他人应用。
- 对外提供的接入配置与实际生效配置一致，避免文档、页面和身份发现结果各自描述不同能力。

### F9：会话管理、退出与撤销联动

- 用户账户中心可以查看自己的中心会话及相关应用登录情况，结束指定会话或退出全部会话。不能查询他人的会话。
- 明确区分退出某个应用、退出当前浏览器的中心会话、退出该用户全部会话。应用本地退出可保留中心会话；当前中心退出覆盖由该中心会话建立的应用授权；全部退出覆盖该用户所有中心会话及关联授权。
- 应用可按 OIDC 标准发起中心退出，退出回调必须事先注册。仅浏览 GET 确认页面不产生未经确认的撤销操作。
- 生产服务端应用可配置经过批准的后通道退出地址；中心按标准发送可验证的退出通知，应用按中心会话关联清除自己的会话。通知具备幂等处理，失败可重试并可观测。
- 中心撤销成功不依赖所有第三方退出地址同时可用，界面分别展示中心撤销结果及通知状态，不将“通知已发送”表述为“第三方已退出”。
- 参考应用必须在保护操作前检查有效会话状态；可用性正常的隔离验收环境中，在中心撤销成功后超过 5 秒发起的保护操作不得成功。
- 第三方应用按审核登记的退出能力执行。仅离线验签且不接受退出通知的应用，无法由中心保证及时清除本地会话；其能力限制必须由管理员明确接受，并在接入说明与应用管理页显示，不宣称满足参考应用的 5 秒撤销目标。

### F10：开发者接入引导与可运行参考应用

- 开发者完成注册后可看到按应用和环境生成的接入指引：签发方、客户端标识、回调、客户端类型、身份范围、凭据使用、身份映射和退出能力。
- 提供一个服务端 Web 参考应用和一个浏览器单页参考应用，使用标准 OIDC 客户端。接入不要求使用本项目内部账户表或业务资源权限库。
- 两个应用在独立站点运行，分别持有自己的会话，提供真实回调与可观察的当前用户信息。测试不使用模拟授权成功结果替代实际身份中心。
- 示例覆盖首次开户、首次登录、跨应用 SSO、强制重新认证、用户未分配、应用停用、中心退出、全局退出与依赖故障。
- 业务应用可以按稳定身份自动建立最少业务资料，中心不承担该应用的业务数据或细粒度业务权限。

### F11：企业管理、账户中心与审计入口

- 企业管理控制台提供开户邀请、用户组、开发者资格、应用审批、用户访问分配、应用停用和审计。
- 开发者控制台提供本人参与的应用、维护人员、开发测试、生产申请、配置结果和凭据管理。
- 用户账户中心提供个人资料、密码、获准应用、授权信息和会话管理；普通用户进入账户中心不需要管理 API 权限。
- 登录失败、访问拒绝、邀请接受、资格变更、申请和审批、访问分配变化、敏感配置变更、密钥重置、会话撤销和退出通知失败均有可检索的记录。
- 管理事件包含操作者、对象、操作、时间、结果和必要的变更信息；不得记录密码、邀请秘密、重置秘密、授权码、完整令牌或密钥明文。
- 管理变更成功记录与实际生效结果一致，不能在提交失败时展示“已上线”“已撤销”或“已重置”。

### F12：历史应用纳管与升级兼容

- 升级保留既有用户、主体标识、客户端标识、签名配置、应用关联和审计历史，不自动清空真实数据库或重建身份。
- 既有客户端以“历史兼容、未纳管”状态可见，在管理员纳管前保留原接入行为，不自动将所有企业用户或新角色授予历史应用。
- 管理员能够核对历史应用负责人、环境、回调、访问范围和退出能力，明确完成纳管；纳管后按本 Spec 的应用准入与变更规则执行。
- 无法可靠判断的应用关联或负责人必须列出冲突并由管理员确认，不能猜测归属或重复创建已存在的客户端。
- 新注册应用一律采用受控准入。历史入口不能成为创建不受控新应用、绕过新审批或扩大已纳管应用权限的途径。
- 升级前后保留现有 MCP 与通用权限能力的有效边界；本轮不向 SSO 用户或新应用自动增加 MCP、机器身份或业务资源权限。

## 非功能需求

- **N1：权限与会话正确性。** 企业身份、开发者资格、应用维护权、用户访问分配、身份披露和业务资源权限分别验证；角色变化和客户端状态变化不能使用过期快照恢复已撤销权限。
- **N2：安全传输与凭据边界。** 生产中心入口和回调使用 HTTPS；中心会话凭据由服务端验证并采用适当 Cookie 保护。浏览器公开客户端使用 S256 PKCE。授权请求、退出请求、邀请、密码重置和管理写入验证来源及证据，失败时不放宽准入。
- **N3：一致性与并发。** 注册、一次性邀请或授权码消耗、配置审批切换、访问分配变更和撤销有可验证的原子生效边界。重复请求、正常并发恢复、真正重放、网络中断和提交失败均具有明确结果。
- **N4：标准兼容。** 使用 OIDC discovery、授权码流程、按客户端类型的认证、ID Token、userinfo、刷新、撤销、内省和退出约定；所宣告能力与实际支持相符。既有扩展字段可以保留，但标准客户端不必理解它们才能登录。
- **N5：可观察的生效时机。** 中心对停用、撤销和准入变化的判断在成功提交后生效；参考应用跨请求的正向会话状态缓存总年龄不超过 5 秒。失败的在线状态验证不能沿用过期的允许结果；不以浏览器页面自动消失作为唯一退出证据。
- **N6：验证与依赖隔离。** 提供业务规则测试、HTTP 与数据库集成测试、新旧数据库升级验证和真实浏览器跨应用验收。数据库和外部通知使用隔离实例，不连接用户业务数据库，不需要真实邮件供应商或第三方 SaaS 账号。
- **N7：交付与运维连续性。** 延续独立部署形态和当前构建检查。以可恢复的版本化迁移升级，给出备份、升级、历史应用纳管和故障诊断说明；本阶段不宣称达到未压测的容量、延迟或 OIDC 认证等级。

## 本轮不做的事

- 多企业 SaaS、多租户共享目录、跨企业账号合并或应用市场分发。
- 匿名开发者直接创建生产应用、公开开发者认证与支付计费。
- 部门树、嵌套用户组、复杂角色继承和业务资源 ABAC/ReBAC 引擎扩展。
- SAML、LDAP/AD 联邦、SCIM、人事同步、社交登录、短信登录、MFA 与 Passkey；这些在核心 SSO 闭环完成后按企业需求另立 Spec。
- 自动邮件投递及公众自助找回密码；第一版通过管理员交付限时邀请和重置链接。
- 任意设备或原业务执行凭据的重新接入；新 SSO 应用不自动获得既有 MCP 或执行权限。
- 对完全未遵守会话联动约定的第三方本地会话作全局退出保证。
- 仅为本轮目标进行全部代码分层重写、独立拆分开放平台服务或全面重设计 UI 风格。

## 验收标准

| 编号 | 对应需求 | 操作与可观察结果 |
| --- | --- | --- |
| AC1 | F1 | 新部署匿名用户无有效邀请时不能建立企业账户；有效邀请开户成功，过期、篡改、并发重复使用均不产生额外身份或资格 |
| AC2 | F1、F6 | 从应用 A 发起授权，接受邀请并开户后返回 A 的注册回调，原客户端、状态与 PKCE 关联正确；邀请不能替换原应用或回调 |
| AC3 | F1、F9 | 修改或管理员重置密码后旧会话被撤销；停用账户后中心新登录、刷新和身份获取被拒绝，参考应用超过 5 秒后的保护操作失败；重新启用不恢复旧令牌 |
| AC4 | F1、F7 | 同一账户资料和资格变更前后，两个参考应用识别到的签发方与主体组合不变；已有账户接受邀请不会建立第二个身份 |
| AC5 | F2、F8 | 开发者只看到和管理本人参与的应用；请求其他应用的配置、成员或密钥被拒绝；合作方不能浏览企业完整目录 |
| AC6 | F2 | 负责人可以交接给具有资格的维护人员；撤销唯一负责人的资格或停用其账户时，系统要求交接或停用应用，不遗留无负责人生产应用 |
| AC7 | F3 | 从开发者界面一次注册后，用生成配置在参考应用完成真实授权码登录，无需补数据库绑定；注入注册提交失败时不能登录半成品，响应丢失后能核对已有结果 |
| AC8 | F3、F8 | 开发与生产凭据和回调彼此独立；SPA 不获得密钥；错误回调、未分配测试人员及跨环境凭据使用被拒绝 |
| AC9 | F4 | 未审批生产应用不能签发生产凭据；另一管理员批准指定配置后可以登录；自批、审批旧版本及审批过程中敏感配置变化不能使未审配置上线 |
| AC10 | F4、F8 | 提交生产敏感配置变更后旧已批准配置继续生效，新配置在批准前不能使用；切换失败不展示已生效；停用与恢复不复活旧令牌 |
| AC11 | F5、F7 | 用户已在中心认证但未被分配应用时不能完成登录；同意身份披露、成为开发者或成为管理员都不能绕过访问分配 |
| AC12 | F5、F9 | 为用户组分配应用后成员可以登录；移除成员后该应用登录和刷新被拒绝，参考应用在目标时间内拒绝保护操作，另一个仍有分配的应用继续可用 |
| AC13 | F6 | A 登录后在新标签页访问不同站点的 B，B 不再要求密码；刷新页面和清除中心当前标签页访问令牌但保留有效中心会话后仍能恢复 SSO；中心会话撤销后不能恢复 |
| AC14 | F6、N3 | 两个应用并发发起授权与正常中心会话恢复均成功；同一授权码或已使用刷新秘密真正重放则被拒绝，且不放宽已有重放撤销规则 |
| AC15 | F6、N4 | 通过标准客户端验证强制重新认证、认证时间限制和无交互请求；无交互但缺少认证或同意时返回标准错误，且没有显示登录或同意页面 |
| AC16 | F7 | 管理员预授权的自研应用在已有认证与分配时自动完成登录；未预授权第三方首次访问要求确认；新增未批准范围不能沿用旧同意而披露 |
| AC17 | F7、N4 | 两个参考应用使用标准 ID Token 获取身份；响应仅包含获准资料，不生成虚构邮箱，不要求业务资源权限，不把 A 的中心或应用访问令牌用作 B 的令牌 |
| AC18 | F8 | 密钥重置后旧密钥不能再认证，新密钥可用，明文后续不可读；另一个环境密钥仍有效；无管理资格者重置失败且无状态变化 |
| AC19 | F9 | 退出 A 本地会话后中心会话仍可用于 B；退出当前中心会话后关联应用授权失效；全局退出覆盖该用户所有浏览器会话，不影响另一用户 |
| AC20 | F9、N4 | 标准客户端发起中心退出后回到已注册退出地址，状态关联正确；伪造退出证据或未注册地址被拒绝，访问 GET 确认页不撤销会话 |
| AC21 | F9、N5 | 服务端参考应用验证后通道通知并幂等清除会话；模拟通知不可达时中心撤销仍成功，失败状态可见并可重试；在线检查失败或过期不能继续允许保护操作 |
| AC22 | F9、F11 | 管理员接入仅具备本地会话的第三方应用时必须确认退出限制，界面和文档可见；通知失败不显示“第三方已退出” |
| AC23 | F10 | 从公开接入说明和两份示例启动两个独立应用，使用本次新注册的配置完成真实跨应用 SSO、身份映射和退出验收，不直接访问中心数据库 |
| AC24 | F11 | 普通账户、开发者和管理员分别看到获准入口；直接调用未获准管理操作仍被拒绝；检索到关键事件的操作者与结果，秘密信息不出现在审计和错误输出中 |
| AC25 | F12 | 新库默认受控开户和应用准入；旧库升级后主体、客户端、签名和历史记录保留，历史兼容状态清晰；确认纳管后新规则生效，冲突不被猜测修复 |
| AC26 | F12、N3 | 经旧客户端管理入口尝试创建新应用或修改已纳管敏感配置，不能绕过资格、审批或分配；既有有效 MCP 边界和刷新重放行为回归通过 |
| AC27 | N1—N7 | 业务规则、隔离数据库/HTTP、并发与失败注入、迁移及真实浏览器验收通过；项目既有构建、格式、静态检查和必要测试通过，证据注明实际环境与执行范围 |

## 首次完整验收路径

1. 管理员建立一个用户组，邀请企业用户、两名开发者及一名合作方。
2. 开发者注册服务端应用 A 和浏览器应用 B，添加维护者，在开发环境用指定测试账户验证登录。
3. 开发者提交生产配置，另一管理员批准，并为企业用户组分配 A、B；合作方仅拥有指定应用维护权。
4. 企业用户从 A 开始接受邀请、注册并登录，再在新标签页进入 B，复用中心认证并完成 B 自己的回调和会话建立。
5. 验证无分配用户、未批准应用、错误回调、无资格开发者和未批准身份范围均被拒绝。
6. 依次验证应用本地退出、当前中心退出、全局退出、用户分配撤销及账户停用，并观察参考应用保护操作、通知状态和审计结果。
7. 使用一份历史客户端数据完成升级和纳管验收，确认身份稳定且没有扩大原有权限。
