# 鱼符产品可用性与发布可信度 Spec

日期：2026-11-13，Asia/Shanghai。状态：用户已于 2026-11-13 明确“确认”批准；进入技术设计，尚未进入实现。

## 背景与目标

用户已选择四组改进：修正对外能力描述并闭合关键发布验收证据；应用直接入口与人员生命周期流程；服务端审计搜索与管理员待办；部署检查、告警与运行状态概览。

当前已有单企业身份中心、OIDC 接入、生产审批、显式访问分配、账户停用撤销、审计、退出通知和容器部署。此次在这些能力上形成完整的操作和验证流程，保持固定 issuer、自托管与默认拒绝的边界。

目标：成员能找到并打开获准应用；管理员能解释访问来源、完成入职与停用、处理待办并检索历史记录；运维能检查部署和定位异常；公开能力与对应版本的真实证据一致。

## 方案选择

| 方案 | 内容 | 优点 | 代价与判断 |
| --- | --- | --- | --- |
| A：现有身份模型上分模块交付（推荐） | 依次交付发布证据、应用与人员流程、查询待办、运行诊断 | 复用现有安全与事务边界，每个模块可独立验收 | 跨模块状态需要统一定义；本规格采用此方案 |
| B：先交付文档与轻量界面 | 修改描述、添加链接和静态操作指引 | 改动较小 | 无法满足全量审计查询、生命周期与运行告警需求 |
| C：整体扩展为企业 IAM 套件 | 同步建设联邦、人员同步、通知平台和自动化管理 | 扩展场景更多 | 超出此次已选范围，兼容与验证成本明显增加 |

## 模块 A：对外描述与发布证据

- F1：README、中英文官网、接入文档和控制台说明采用一致的能力状态：已验证可用、已实现待验收、兼容保留、暂不支持。旧文档中的历史记录保留日期与上下文，不作为当前版本的成功声明。
- F2：公开能力清单区分中心内部能力和外部应用可用接口。当前不能正常提供外部决策的 PDP 接口不得描述为可直接接入；此次不通过放松身份验证恢复旧决策接口。
- F3：为候选发布建立证据索引，记录源码版本、工作区改动状态、命令、环境、时间、退出状态、测试数量及证据位置。后续修改影响相关行为时，对应证据需重新验证。未执行、失败和受环境阻塞分别记录。
- F4：关键发布验收覆盖已有企业 SSO 规格中的 E5 准入拒绝、E6 撤销与退出矩阵、E7 公开文档复现及升级恢复；补齐邀请开户后继续原应用授权。复用已有证据必须说明源码和覆盖范围仍适用，不凭测试名称或数量勾选验收。
- F5：关键验收在隔离实例使用真实身份服务、两个独立应用及保护 API，浏览器场景覆盖 Chromium、Firefox、WebKit。记录三平台 CI 的实际结果；拿不到远端结果时保留阻塞，不能以本机成功代替。质量门禁失败不得标记发布验收完成。

## 模块 B：应用入口与人员生命周期

- F6：为每个应用环境维护可选的启动地址和说明。修改权限、生产审批及配置生效规则与现有环境配置保持一致。生产启动地址只接受无用户名密码的绝对 HTTPS 地址；开发环境另允许现有规则认可的本机 HTTP 地址。拒绝脚本、数据、相对和协议相对地址。读取列表时不主动抓取目标地址。
- F7：成员仅能看到当前有效准入范围内的环境；已生效且已配置启动地址的环境提供“打开应用”。按钮跳到应用入口，由应用发起标准 OIDC 登录，不直接拼装授权凭据。未配置地址显示原因；打开前重新检查可用性，撤权后不能继续使用中心入口，应用授权仍执行独立实时检查。历史环境缺少启动地址时继续可读取和管理。
- F8：普通成员默认查看生产环境，可切换到自己有权访问的开发环境。开发维护关系与生产访问分配仍分别计算，应用卡片显示准入来源；不得因增加入口让未获分配的生产应用可见或可登录。
- F9：管理员可建立入职流程，选择人员类别、开发者资格、初始用户组与直接应用分配，签发邀请并跟踪待接受、已接受、过期、撤销和待完成配置。邀请接受后关联唯一账户，再应用仍有效的预选分配；每个步骤独立给出结果，失败可安全重试，不得声称跨步骤已原子完成。预选关系不在邀请接受前授予访问；配置被删除或管理员资格已撤销时不得照旧自动授权。
- F10：账户详情解释有效访问及其全部来源，至少区分直接分配、用户组继承、开发维护关系和测试访问。对同一环境展示多条来源；移除一条但仍有其他来源时明确说明仍可访问。岗位调整通过修改现有关系完成，提交前展示预计访问变化并使用当前版本执行并发检查。
- F11：停用前展示有效访问、中心与应用会话、负责或维护的应用及其处理要求。停用提交成功后记录本地撤销结果，分别展示后通道通知待发送、送达、失败状态；通知接收不宣称应用内部会话已清理。若触发现有最后管理员或应用负责人约束，说明需先转交的对象，不得绕过约束。再次启用不恢复旧会话；保留的分配关系需展示，重新登录后按当前关系计算访问。
- F12：邀请、人员流程与访问变更均可追溯；一次性链接秘密仅在签发结果中短暂展示，状态列表不返回秘密。邀请撤销、重复接受、流程重试和并发操作不产生重复账户、重复分配或越权。

## 模块 C：服务端审计搜索与管理员待办

- F13：审计查询在服务端对全部有权读取的记录生效，支持时间范围、操作者、应用、操作、对象类型与标识、结果和请求标识。应用条件关联真实应用事件语义，不把任意对象数字当应用标识。组合条件按交集处理；无法关联到应用的事件不猜测归属。无筛选时保持现有列表可用。
- F14：搜索结果采用稳定分页。筛选变化回到第一页，分页保持同一筛选，时间边界明确展示时区；同一时刻记录用稳定次序区分。并发插入不导致旧页遍历重复；刷新会开启新一轮查询。界面区分已加载条数与全量统计，不将当前页数量标为全局总数。错误和超时不得呈现为空结果。
- F15：管理员工作台展示全量聚合的待生产审批、入职待处理、退出通知异常与运行告警数量，并提供对应筛选列表入口。聚合不依赖浏览器已加载页。普通成员与开发者不读取管理员统计；无法读取的模块显示未知或失败，不能显示零。
- F16：待办展示对象、原因、发生时间、当前状态和处理入口；审批或其他状态变化后刷新统计与列表。计数和列表标注采样时间，允许并发更新导致短暂变化，不承诺跨页面固定快照；不得提供绕过既有权限检查的快捷处理。

## 模块 D：部署检查、告警与运行状态

- F17：提供可独立运行的只读部署检查，逐项验证配置合法性、公开 issuer 与 Origin 一致性、密钥存在且可读及格式、数据库连接和迁移状态、可信时钟、Discovery 可用性。离线配置检查与需要网络或运行中服务的检查分别呈现；无法执行的检查标为未验证，不自动算通过。检查不启动迁移、不改配置、不生成或覆盖生产密钥。
- F18：检查输出同时适合人工阅读和自动化消费，包含检查项、通过/警告/失败/未验证、脱敏原因、修复建议与采样时间；存在失败或必需项未验证时返回非成功状态。非本机 HTTP、缺失密钥和时钟不可信等问题仍遵守现有安全限制，不提供一键绕过。
- F19：管理员运行概览显示服务版本与启动时间、数据库状态、认证时钟同步与偏差、退出通知积压数量及最老等待时间、通知失败数量和最近状态采样时间。数据库不可达、时钟异常、来源不支持的值显示未知或异常，不沿用旧绿色状态。整体就绪状态与服务现有就绪检查保持一致。
- F20：内置告警覆盖数据库不可用、认证时钟不可信、退出通知持续积压和永久失败。默认每 30 秒评估；积压最老年龄超过 5 分钟持续两个评估周期触发，允许配置阈值并验证合理范围；永久失败下一次评估触发。同一原因与对象只保留一个活动事件，记录首次/最近发生、严重程度、触发值与恢复时间。确认只标记已读，不代表恢复；进程重启不丢失尚未恢复的事件。数据库不可用时通过进程日志和外部探测表达故障，恢复连接后再持久化，不能要求故障数据库先成功写入。
- F21：本期告警渠道为管理员站内列表与脱敏结构化日志，提供受控的机器可读运行状态用于现有监控系统接入，并说明进程退出或整机不可达需外部探测。详细状态仅供获授权管理员或监控调用方访问，公开探针仅保留最小健康信息。部署文档提供外部探测示例；本期不发送邮件、Webhook 或企业 IM 消息。

## 非功能需求

- N1 安全：复用中心 Cookie、Origin、CSRF、精确授权、版本检查和既有幂等语义；每条新增读取均检验对象可见范围。启动地址不是认证回调地址，不改变既有回调校验。
- N2 兼容：使用追加迁移，保留历史迁移标识、业务数据、固定 issuer 和原密钥；旧环境启动地址默认未配置。新增字段不改变历史准入与令牌语义。
- N3 隐私：页面、日志、指标、检查输出及验收附件不包含密码、连接串秘密、私钥、令牌、邀请证明或客户端密钥。自动化证据只使用虚构账户和隔离配置。
- N4 查询成本：搜索和聚合在服务端执行，不为计算全量结果逐页下载目录；限制条件长度与分页大小；监控采样和查询不得占用无界资源。验收以十万条审计和一千账户的隔离数据集验证，记录硬件、数据规模及延迟；本机目标为预热后审计查询和工作台聚合各 P95 不超过 1 秒，不能外推为生产 SLA。
- N5 故障语义：本地撤销、消息发送、接收和应用实际清理分别报告。异步步骤以可重试状态呈现；失败保留已成功事实。接口故障、未知和空数据不得混为一类。
- N6 可操作性：新增表单、结果、待办和告警具有加载、空、失败、重试与键盘操作状态；危险操作明确展示对象和影响。已有中英文产品文档同步更新。
- N7 验证隔离：数据库与端到端测试使用可销毁实例、临时密钥和独立端口；数据库集成测试串行执行，不访问业务数据库，不修改本地真实配置，不主动触发公开发布或生产部署。

## 不做的事

不新增多租户、公开应用市场、MFA、SAML、LDAP、SCIM、外部 IdP 联邦、M2M、管理 SDK、通用工单平台、HR 同步或自动权限推荐；不建设可调用任意地址的监控探测器。保留公开 PDP 的准确状态说明，恢复或设计新 PDP API 需另立需求。

本次不包含多语言 SDK 扩展和完整接入向导。人员流程只覆盖邀请入职、现有关系调整和停用离职，不覆盖未来日期定时生效及审批组织编排。站外告警发送需后续明确渠道、凭据、接收对象与投递策略。

## 交付顺序与完成定义

1. 统一能力状态与证据规则，核对既有验收缺口，建立候选版本基线。
2. 交付环境启动地址、成员入口与人员流程，完成越权及撤销回归。
3. 交付服务端审计搜索、全量聚合与待办，验证跨页数据和查询成本。
4. 交付只读部署检查、运行概览和告警，验证异常、恢复及监控接入。
5. 对最终候选版本执行关键发布场景与质量门禁，更新公开说明和证据索引。

完整交付要求以上四个模块行为验收及关键发布门禁全部通过。中间模块完成不等于发布验收闭合；无法取得的证据单列阻塞并保留未完成状态。
