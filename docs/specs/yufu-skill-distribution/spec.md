# yufu Skill 独立分发 Spec

> 状态：已批准
> 范围：把现有 `yufu-onboarding` Skill 变成可通过 skills CLI 安装、在任意 Go 项目中独立运行的产物

## 背景

现有 Skill 只在与 yufu 源码同仓时可用：脚本用相对路径定位仓库根，依赖根 `compose.yaml`、
`target/debug/yufu` 和 `examples/sdk/go/go.mod`。一旦通过 `npx skills add` 安装到使用方项目，
这些路径全部失效，部署和接入会在第一步就失败。

skills.sh 的 CLI 已把 `.agents/skills/` 列为标准扫描目录，因此该 Skill 的仓库位置本身不需要搬家；
真正缺的是运行期自包含：不依赖源码 checkout、不要求 Rust 工具链、版本与校验和固定。

## 目标

- 使用方在任意 Go 项目中执行一条安装命令，即可获得可运行的 Skill，无需 clone yufu 仓库。
- 安装后的 Skill 只依赖自身目录、Docker、curl、python3 与 Go，不再假设 yufu 源码存在。
- 用一句话触发的流程可完成「部署 → 注册 → 校验」，并停在需要真人操作的最小点。
- 部署产物与 SDK 版本可复现：固定版本号与校验和，不使用浮动版本。
- 同一个 Skill 在 yufu 仓库内仍按开发模式工作，不强迫开发者走下载路径。

## 功能需求

- **F1 自包含运行**：安装到使用方项目后，Skill 的全部脚本、模板、文档只引用 Skill 目录内部资源；
  不得通过相对路径访问 Skill 目录之外的文件。使用方项目根仅用于写入接入代码与本地状态目录。
- **F2 二进制获取**：按优先级选择 yufu 可执行文件——显式指定的本地二进制 → 检测到的源码构建产物
  → 本地缓存 → 按当前平台下载固定版本的官方发布包。下载路径不要求 Rust 或 cargo。
- **F3 下载校验**：下载后必须用 Skill 内固定的校验和验证归档；校验失败立即终止，不落盘可执行文件、
  不继续启动服务。平台不在支持列表时给出明确错误。
- **F4 自包含数据库**：Postgres 的启动方式不再依赖 yufu 仓库的 compose 文件，Skill 自带等价的单服务
  定义；已在运行的兼容实例直接复用，不重复创建容器或数据库。
- **F5 版本固定**：yufu 版本、各平台校验和、Go SDK 版本集中记录在 Skill 内；代码生成与文档引用同一来源。
  仓库内提供一致性检查，任一处版本漂移即失败。
- **F6 单一非交互入口**：提供一条命令完成「前置检查 → 部署 → 注册 → 参数校验」，接收接入形态参数，
  不需要逐步确认；成功时输出一段交接信息（issuer、client id、secret 文件位置、下一步），
  失败时指出阶段与可执行的排查命令。
- **F7 一句话触发**：Skill 的描述与入口章节必须让 agent 在听到「部署 yufu 并接入这个项目」时
  直接进入执行流程，而不是先解释背景；除接入形态外不再追问。
- **F8 双模式兼容**：在 yufu 源码仓库内运行时识别开发模式，优先使用本地构建产物与仓库内数据库定义；
  不触发下载，不覆盖开发者已有配置。
- **F9 文档同步**：所有引用仓库内专有路径的说明改为「按 Skill 内的资源」或「按固定版本」表述，
  安装后不存在指向不存在文件的指引。
- **F10 发布与发现**：以公开仓库 + 语义化标签发布，README 给出带 Skill 名与版本的安装命令；
  安装后可通过 skills CLI 列出该 Skill，并能在 skills.sh 上检索到。
- **F11 安装完整性**：Skill 被复制或软链到使用方项目后，所有脚本以解释器显式调用，不依赖可执行位；
  目录内不得残留绝对路径或构建机专属信息。

## 非功能需求

- **N1 凭据安全**：client secret 只写入权限 600 的本地文件，不打印、不进入前端、不提交；下载校验和
  防止被替换的二进制被执行。
- **N2 可复现**：安装命令固定到标签；部署版本与 SDK 版本固定；重复执行结果一致。
- **N3 环境基线**：macOS（Intel / Apple Silicon）与 Linux x86_64；bash 3.2 兼容；python3 标准库；
  不引入 jq 等额外依赖。
- **N4 非侵入**：对使用方项目只新增接入文件、状态目录和 `.gitignore` 条目；不改造目录结构、
  不覆盖无关文件、不自动提交。
- **N5 可诊断**：每个失败都落到具体阶段，并给出至少一条可直接执行的校验命令；不得出现
  「未知错误」式输出。
- **N6 离线可解释**：无网络且无缓存时明确失败并提示本地二进制入口，不静默降级到源码构建。
- **N7 发布面最小**：Skill 内不含二进制、不嵌入任何真实凭据；CLI 上报的 Skill 文件不包含敏感信息。

## 不做的事

- Windows 原生支持（脚本基于 bash，首版只覆盖 macOS / Linux）
- 把 Skill 拆成独立仓库（保留在 yufu 仓库，等出现非 yufu 维护者再评估）
- 通过 skills.sh API 主动提交收录、付费推广或定制页面
- Python / Node SDK 的接入实现
- 生产部署：TLS、域名、反向代理、多机、密钥托管
- 自动完成浏览器登录或控制台人工审批
- 修改 yufu 服务端接口、管理 API 或 `yufu-sdk-go`
- 为使用方自动提交代码或创建 PR

## 验收标准

- **AC1（F1/F11）**：在空 Go 项目中按标签安装后，Skill 目录内搜索不到越出自身目录的相对路径、
  绝对路径或构建机路径；`skills` CLI 能列出该 Skill。
- **AC2（F2/F6）**：在无 yufu checkout、无 cargo、有 Docker 的环境中，用一句话触发，最终
  discovery 可用、应用注册成功、注册参数校验通过，并输出交接信息。
- **AC3（F2/F3）**：把下载归档替换为损坏内容，流程在启动任何服务前失败，退出码非零，
  不留下可执行文件。
- **AC4（F4）**：第二次执行复用已就绪的 issuer、数据库与应用，不新建容器、不新建库、不产生第二个应用。
- **AC5（F5）**：生成的 Go 模块使用 Skill 内固定的 SDK 版本；人为改动任一处版本后一致性检查失败。
- **AC6（F8）**：在 yufu 仓库内执行时不下载发布包，优先使用本地构建产物；行为与改造前一致。
- **AC7（N6）**：断网且无缓存时，错误信息包含可用的本地二进制入口，且未尝试源码构建。
- **AC8（F9）**：安装副本中所有「查看示例 / 查看 compose」类指引均指向 Skill 内资源或固定版本，
  不存在指向 monorepo 文件的死路径。
- **AC9（F7）**：新会话中只给一句「部署 yufu 并接入这个项目」，agent 直接开始执行，
  只询问接入形态（Web 登录 / 保护已有 API）。
- **AC10（F10）**：公开仓库按标签安装成功；README 安装命令可直接复制执行；skills.sh 上可检索到
  该 Skill 并展示安装入口。
