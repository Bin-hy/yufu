# yufu Skill 独立分发 Checklist

> 输入：`spec.md`、`plan.md`、`task.md`（均已批准）
> 判定方式：运行命令或观察行为，记录退出码与输出作为证据；不以「代码看起来对」为通过依据。
> 人工项单独标注，不由自动化结果代替。

## 实现完整性

- [ ] 安装副本的 Skill 目录自包含：脚本、模板、文档只读取目录内部资源（验证：在空项目安装后，搜索 `\.\./\.\./`、`examples/sdk`、`<repo>`，均无命中）
- [ ] 平台识别覆盖 macOS arm64、macOS x86_64、Linux x86_64；其他平台明确拒绝（验证：正常平台输出对应 target；`YUFU_TARGET=windows` 运行前置检查，退出码非零并列出支持项）
- [ ] 二进制按四级优先级解析：显式指定 → 源码产物 → 缓存 → 下载（验证：分别设置 `YUFU_BIN`、在仓库内运行、复用已有缓存、清空缓存离线运行，四种场景各得到预期来源）
- [ ] 下载后校验和不符时不落盘、不启动（验证：改用全零校验和，清空工作目录后执行部署，确认无 `bin/` 产物且服务未启动）
- [ ] 数据库定义随 Skill 提供，不读取外部 compose 文件（验证：把 Skill 复制到 `/tmp`，移走仓库后运行部署，容器正常启动）
- [ ] 版本与校验和集中在一处，生成代码与文档同源（验证：对比版本文件、脚手架生成结果、文档引用，三处版本一致）
- [ ] 单条命令可完成「前置检查 → 部署 → 校验 issuer → 注册 → 校验参数」（验证：在空项目执行一次，四阶段全部成功并输出交接块）
- [ ] 交接块包含 issuer、client id、secret 文件位置、下一步参考文档（验证：逐项核对输出，secret 文件权限为 600）
- [ ] 失败时输出阶段名与至少一条可执行排查命令（验证：分别制造前置失败、下载失败、注册失败，观察输出）

## 集成

- [ ] 部署阶段调用二进制解析，不再硬编码源码构建路径（验证：仓库内运行的来源标记为本地产物；安装副本运行的来源标记为下载或缓存）
- [ ] 数据库阶段复用运行中的兼容实例（验证：连续执行两次，第二次不重建容器、不重复建库）
- [ ] 脚手架生成的 Go 模块锁定版本文件中的 SDK 版本（验证：查看生成的 `go.mod`，版本等于版本文件）
- [ ] 所有文档指引指向 Skill 内资源或固定版本（验证：搜索安装副本的全部 Markdown，无 monorepo 路径）
- [ ] 注册后的参数校验使用同一份状态（验证：注册结束自动进入校验，issuer、client id、回调地址一致）
- [ ] 使用方项目只新增接入文件、状态目录与忽略条目（验证：在空 Git 项目执行前后对比 `git status`，无其他改动）

## 安全与兼容

- [ ] client secret 不出现在终端输出、日志或已跟踪文件中（验证：全流程输出搜索 secret 内容无命中；`git status` 不含状态目录）
- [ ] 状态目录权限为 600，且被忽略（验证：`ls -l` 与 `git check-ignore`）
- [ ] Skill 内不含二进制、归档或真实凭据（验证：查找可执行文件与 tar/zip，无命中）
- [ ] 无网络且无缓存时明确失败，并提示本地二进制入口（验证：设置不可用代理后执行，输出包含 `YUFU_BIN`，未尝试源码构建）
- [ ] bash 3.2 下脚本语法与运行正常（验证：所有脚本 `bash -n` 通过；在 macOS 默认 bash 下执行一次完整流程）

## 编译与测试

- [ ] 所有 Skill 脚本语法检查通过（验证：`bash -n` 遍历脚本，退出码 0）
- [ ] 仓库工具测试全部通过（验证：`python3 scripts/readiness.py run tool-tests`）
- [ ] 一致性测试能捕获版本漂移（验证：临时改动 SDK 版本后运行测试，失败；还原后通过）
- [ ] 生成的资源服务器代码测试通过（验证：`go test ./...` 覆盖无令牌 401、有效令牌 200、audience 不符、过期）
- [ ] Web 接入示例可构建（验证：`go build ./...` 通过）

## 端到端场景

- [ ] 场景 1（AC2，全新使用方）：空 Go 项目从默认分支安装 → 一句话触发 API 模式 → issuer 可用、应用注册成功、参数校验通过、打印交接块（验证：记录阶段输出与 `state.env` 关键键）
- [ ] 场景 2（AC4，幂等）：同一项目重复执行 → 复用 issuer、数据库与应用，不新增容器、不新建库、不产生第二个应用（验证：对比两次的容器创建时间、应用数量与 client id）
- [ ] 场景 3（AC6，开发模式）：yufu 仓库内执行 → 不触发下载，使用本地产物，已有配置不被覆盖（验证：来源标记为本地产物；核对配置与状态文件未被重置）
- [ ] 场景 4（AC3/AC7，失败路径）：损坏归档与断网各执行一次 → 启动服务前失败、退出码非零、无残留可执行文件、错误信息可操作（验证：检查退出码、`bin/` 目录与服务进程）
- [ ] 场景 5（Web 路径）：按参考文档接入 → `/login` 返回 302 跳转 issuer → 人工浏览器登录后受保护接口返回稳定 `sub` → `/logout` 后重新要求登录（验证：`curl` 状态码与重定向地址；浏览器结果人工记录）
- [ ] 场景 6（AC9，一句话触发）：新会话只输入「部署 yufu 并接入这个项目」→ agent 直接进入前置检查，只追问 Web 登录或保护 API（验证：记录新会话实际提问，不超过一个形态问题）

## 发布与发现

- [ ] 标签内容包含改造后的 Skill（验证：`git show <tag>:…/SKILL.md` 包含快速路径与版本来源）
- [ ] README 安装命令可直接复制执行，标签与远端一致（验证：在空目录复制执行，安装成功）
- [ ] 公网从默认分支安装后 `skills list` 显示该 Skill（验证：`npx skills list` 输出包含 `yufu-onboarding`）
- [ ] skills.sh 页面可检索并展示安装入口（验证：访问对应页面；索引延迟时记录实际状态，不记为通过）
- [ ] 安装副本可独立完成预检与部署，无仓库依赖（验证：在 `/tmp` 空项目运行前置检查与部署）
