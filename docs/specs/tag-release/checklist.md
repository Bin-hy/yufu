# Tag 自动打包与发版 Checklist

依据已批准的 [spec.md](spec.md)、[plan.md](plan.md) 和 [task.md](task.md)。
本清单待批准；批准后开始实现。当前所有项目未执行，不能视为已通过。

## 版本与触发（AC1；F1、F2）

- [ ] C01：稳定 tag `v1.2.3` 与匹配的临时 manifest/lockfile 校验通过，输出版本 `1.2.3` 且非 prerelease。（验证：发布工具单测与 CLI 调用。）
- [ ] C02：`v1.2.3-alpha.1`、`v1.2.3-beta.2`、`v1.2.3-rc.3` 校验通过并标记 prerelease。（验证：参数化版本测试。）
- [ ] C03：无 v 前缀、缺少版本段、多余前导零、无编号预发布、未知后缀、shell 特殊字符及其他非法 tag 被拒绝。（验证：失败用例返回非零，不产生有效发布输出。）
- [ ] C04：tag 与 workspace 版本不符、任一 workspace 包锁版本不符或版本来源缺失时失败，并指出原因。（验证：临时文件测试。）
- [ ] C05：workflow 仅由 tag push 进入，非法 `v*` tag 在预检失败后不会进入门禁、打包或发布；分支 push 与 PR 不触发本流程。（验证：actionlint 与触发/依赖配置检查。）

- [ ] C08：集成测试配置具备 Docker/testcontainers 和所需浏览器依赖，不指向用户业务数据库。（验证：workflow 与现有隔离测试夹具配置核对；可用环境运行并记录。）
- [ ] C09：cargo-machete 与 cargo-audit 纳入门禁，无静默忽略、`continue-on-error` 或吞掉退出码。（验证：workflow 检查与可用环境实际运行；失败项如实记录。）

## 发布状态与失败重试（AC6、AC7；F8—F10）

- [ ] C21：最终发布依赖质量门禁及全部构建成功，不存在失败后仍执行公开操作的条件。（验证：job DAG 与条件检查。）
- [ ] C22：发布前远端 tag 解引用提交须与本 run 一致；tag 被移动时失败，不创建或修改 Release。（验证：GitHub CLI 替身演练。）
- [ ] C23：查询 Release 仅将 404 视为不存在；认证、权限、网络或其他 API 错误直接终止。（验证：替身分别返回各类失败，断言无后续写入。）
- [ ] C24：已公开 Release 不可被重跑覆盖；其他流程/提交创建的草稿不被改动。（验证：替身构造公开、无标记草稿及提交不匹配草稿，断言拒绝。）
- [ ] C25：可创建新草稿，或复用本流程同 tag、同提交的草稿；同 tag 并发互斥且不自动取消正在发布的 run。（验证：替身演练和 concurrency 配置检查。）
- [ ] C26：草稿上传后复核恰好四包与 SHA256SUMS，核对附件大小，下载并验证摘要后才能公开。（验证：完整替身流程与附件缺失/大小不符/摘要不符用例。）
- [ ] C27：上传中断或校验失败后草稿保持未公开；重新运行可清理归属明确的旧草稿附件并完成，不删除 tag。（验证：失败→重试的两阶段替身演练。）
- [ ] C28：稳定版本生成正式 Release，alpha/beta/rc 生成 prerelease；说明包含自动变更记录、tag、提交、平台及安装校验入口。（验证：替身记录最终请求与生成说明内容。）

- [ ] E05：真实四平台 Actions 与真实 GitHub Release 发布通过。（验证：未来首次正式推送匹配版本 tag 后的 job/Release 链接；本次范围明确不创建 tag 或 Release，因此交付时保留待远端验证。）

## 状态记录规则

- 只有命令或可观察行为通过后才勾选；静态配置存在不能代替真实平台运行。
- 每个条目在 verification.md 中关联证据；阻塞或失败单独列出原因及下一步。
- Mock/替身证明分支逻辑，不证明 GitHub 令牌权限、托管 runner 构建或真实 API 写入已经成功。
- E05 留待真实发版验收；不得为勾选该项擅自创建 tag、推送或公开 Release。
