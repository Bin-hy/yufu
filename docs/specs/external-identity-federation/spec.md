# 外部身份社交登录（GitHub / QQ / 微信扫码）Spec

> 状态：已批准；P3–P6 已实现（2026-11-27）
> 范围：P3–P6 剩余工作；P1/P2 已实现基线不在本 spec 重做
> 非范围：Yufu 官方微信小程序、`wx.login`、`/mini/*`、handoff/resume

## 背景

Yufu 是唯一的核心身份认证中心，下游应用通过标准 OIDC 接入。当前已完成：

- 外部身份数据模型、Provider 抽象、Secret 加密存储、限流、审计与迁移（P1）。
- GitHub OAuth 登录、绑定、解绑，以及登录页和账户中心第三方身份页（P2）。
- 现有 OIDC Discovery、授权、Token、UserInfo、会话与撤销流程保持不变。

本次要补齐剩余社交登录能力。经确认，**Yufu 不开发自己的微信小程序**，也不承担 `wx.login`、小程序专用会话、handoff/resume 等“Yufu 官方小程序”能力。未来其他项目可以有自己的小程序，通过标准 OIDC 接入 Yufu，并在 Yufu 登录页选择“微信登录”。

微信 Web 登录采用**微信开放平台网站应用扫码登录**：桌面浏览器展示微信官方扫码页，用户用手机微信扫码授权后回到 Yufu。该方式不能检测本机微信客户端是否已登录，也不覆盖微信内置浏览器/公众号网页 OAuth。

## 目标

- 用户可以使用 **微信扫码** 和 **QQ** 登录 Yufu，并与 GitHub 一样进入原有用户、会话和 OIDC 授权流程。
- 已登录用户可以在账户中心绑定/解绑微信、QQ 身份；未绑定时默认拒绝第三方登录，管理员可配置为自动创建无密码外部账号。
- 管理员可以在控制台配置 GitHub/QQ/微信 Provider、写入/轮换 Secret、启用/禁用，并查看登录成功/失败统计。
- 所有新增能力默认关闭，数据库迁移对既有部署兼容，不改变下游 OIDC 接入方式。
- 在微信开放平台/QQ 应用资质未就绪时，通过 fake Provider 完成可重复的自动化验收；资质就绪后再做真实联调。

## 成功标准

- 微信扫码与 QQ 登录、绑定、解绑在 fake Provider 下端到端通过；GitHub 可真实联调。
- 未绑定默认被拒绝；`registration = open` 时可创建无密码外部账号，且不会按邮箱/昵称自动合并。
- 管理员配置后登录页即时反映；Secret 永不回显，停用后登录入口消失。
- 现有 OIDC 客户端、Discovery、Token、UserInfo 与会话行为无回归。
- 全部新增行为有审计；最后一个登录凭据不可解绑。

## 功能需求

### F1 微信扫码登录

- 登录页仅展示“已启用且配置完整”的微信登录入口；未配置或禁用时不展示。
- 用户选择微信登录后，Yufu 生成一次性登录事务，并跳转到微信开放平台官方扫码页；用户用手机微信扫码并确认授权。
- 微信回调携带授权码与状态；Yufu 必须校验状态的一次性、有效期和浏览器绑定，再在服务端使用 AppSecret 换取微信身份。
- 微信身份以 `openid` 作为稳定外部标识；若返回 `unionid` 则保存但**不用于自动合并账号**。
- 微信接口返回的 `access_token`、AppSecret 等只允许在服务端使用，不得返回浏览器或写入前端存储。
- 已绑定微信身份时，Yufu 建立正常的中心会话，并继续原有 OIDC 授权事务；下游应用不感知登录方式。
- 未绑定微信身份时，按 F4 的注册策略处理。
- 用户取消授权、状态无效/过期、微信返回错误、账号被禁用、身份已绑定其他用户等情况，都不得建立会话；返回稳定的错误分类并写审计。
- 微信官方扫码页不可用时，应返回可重试错误，不得伪造登录成功。

### F2 微信身份绑定与解绑

- 已通过 Yufu 身份认证的用户可以在账户中心发起微信绑定；未认证用户不能直接绑定。
- 绑定完成时必须再次确认当前会话仍有效，不能把微信身份绑定到发起绑定之外的账户。
- 同一微信身份（同一 Provider 的同一 `openid`）只能绑定一个 Yufu 用户；已属于其他用户时拒绝，且不泄露对方账户信息。
- 第一阶段每个用户在同一 Provider 下只保留一个身份；重复绑定同一身份按幂等成功处理。
- 账户中心展示已绑定微信的基本标识、绑定时间和最近登录时间。
- 用户可以解绑微信；解绑不得影响密码、GitHub、QQ 等其他登录方式，也不得强制撤销现有会话。
- 解绑后若用户已没有任何可用登录凭据（无密码且无其他外部身份），必须拒绝解绑。
- 绑定、解绑、拒绝都必须写入审计。

### F3 QQ 登录、绑定与解绑

- QQ 使用官方 OAuth 2.0 授权码流程；登录页仅展示已启用且配置完整的 QQ 入口。
- 服务端校验状态的一次性、有效期和浏览器绑定；在服务端用 AppKey 换取访问令牌。
- 使用 QQ `openid` 作为稳定外部标识；昵称、头像只作为展示信息，不参与身份匹配。
- 已绑定 QQ 时建立正常中心会话并继续 OIDC；未绑定时按 F4 处理。
- 绑定、解绑、重复绑定、最后凭据保护与 F2 相同。
- QQ 返回格式差异（包括非标准 JSONP/错误结构）由服务端兼容解析；任何解析失败都不得导致登录成功。
- QQ 应用资质未就绪时，Provider 默认禁用；必须能用 fake Provider 完成端到端验收。

### F4 未绑定身份的注册策略

- 系统支持两种生效策略：
  - `disabled`（默认）：未绑定身份不得登录，也不自动创建 Yufu 账户；返回稳定错误，提示先使用 Yufu 账号登录并绑定。
  - `open`：未绑定身份首次登录时自动创建无密码的 Yufu 外部账号，并建立绑定。
- `invite_only` 保留为后续策略占位；在实现前按 `disabled` 处理。
- 自动创建的账号：
  - 没有密码，不能通过密码登录；
  - 使用服务端生成的唯一用户名，默认普通用户/合作方，不授予管理员或开发者权限；
  - 必须有对应的 Yufu `sub`，但第三方 `openid` 绝不作为 `user_id`。
- 禁止仅凭相同昵称、相同邮箱或未验证邮箱自动合并账号。
- 同一第三方身份不得绑定多个 Yufu 用户；并发首次登录不得创建重复账号或重复绑定。

### F5 管理端 Provider 配置

- 管理员可以查看 GitHub、QQ、微信的配置状态：是否启用、是否已配置 Client ID/AppID、是否已配置 Secret、更新时间、revision。
- 管理员可以配置或修改：
  - GitHub：Client ID、Client Secret；
  - QQ：AppID、AppKey；
  - 微信：开放平台网站应用 AppID、AppSecret。
- Secret 只允许写入和轮换，任何读取接口、日志、审计摘要和前端都不得返回 Secret 明文；只可返回“已配置”及必要的末位提示。
- 启用 Provider 前必须满足配置完整性；配置不完整时不能启用。
- 管理员可以启用/禁用 Provider；禁用后：
  - 登录页不再展示该入口；
  - 新的登录/绑定发起被拒绝；
  - 已绑定身份仍可在账户中心查看和解绑。
- 配置写入必须具备并发版本控制；版本冲突时拒绝并提示刷新，不能静默覆盖他人修改。
- 配置变更必须写审计，审计中不得包含 Secret。
- 配置变更后无需重启服务即可生效；登录页与发起接口立即反映新状态。
- 环境变量引导仅用于首次空配置，不得覆盖管理端已保存的配置或 Secret。

### F6 登录统计与异常查看

- 管理员可以按 Provider 和时间范围查看登录成功数、失败数和主要失败分类。
- 统计数据来源于既有审计记录，不新增敏感数据采集。
- 至少支持最近 24 小时与最近 7 天两个时间范围。
- 统计结果不得包含第三方 Secret、授权码、访问令牌或完整外部身份标识。
- 统计口径必须区分：登录成功、用户拒绝/取消、未绑定被拒绝、上游不可用、配置/状态错误。

### F7 Provider 可用性与隔离

- 公共登录方式列表只包含已启用且配置完整的 Provider。
- 未启用 Provider 的发起、回调和绑定接口必须失败关闭，不能因为残留会话或旧链接而完成登录。
- 单个 Provider 故障、超时或配置错误不得影响其他 Provider、密码登录和现有 OIDC 客户端。
- 微信、QQ、GitHub 的登录/绑定/解绑行为必须一致：同一套会话建立、审计、限流、解绑保护与错误分类。
- 下游 OIDC 客户端不需要修改接入配置，也不感知用户使用了哪个 Provider。

## 非功能需求

### N1 OIDC 兼容性

- 不改变 OIDC Discovery、授权、Token、UserInfo、JWKS、撤销和会话接口的路径与语义。
- 已有 OIDC Client 不需要修改 `redirect_uri`、scope、PKCE 或令牌校验方式。
- 第三方登录成功后只影响“如何认证用户”，不改变下游获得的 `sub`、ID Token、Access Token 或 Refresh Token 规则。
- 新增表、字段和配置不得改变既有 `identity_subject` 的 `sub = user_id` 约束。

### N2 安全与防滥用

- 上游登录状态必须是一次性、不可预测、短时有效，并绑定发起登录的浏览器。
- 回调地址必须是服务端固定值，必须与外部平台登记值一致；不接受请求传入的任意回调地址。
- 支持 PKCE 的 Provider 必须使用 S256；不支持 PKCE 的 Provider 必须依赖固定回调、服务端 Secret、一次性 code/state 和短时有效期。
- 授权码、state、访问令牌只允许一次性使用；重放必须被拒绝。
- 第三方身份唯一性由持久化唯一约束保证；绑定完成时必须重新校验当前用户会话。
- 禁止仅凭邮箱、昵称或未验证资料合并账号。
- 登录、回调、绑定、解绑、管理端配置变更必须有频率限制；超限不得影响其他 Provider 或密码登录。
- 未启用或配置不完整的 Provider 必须失败关闭，不能通过旧链接、旧会话或回调绕过。
- 最后一个可用登录凭据不可解绑。

### N3 事务与超时隔离

- 外部平台 HTTP 调用不得占用核心身份写事务；不得在持有数据库行锁时等待第三方响应。
- 上游调用必须有独立、可配置的超时和并发上限；上游超时/错误不得留下半完成会话或错误绑定。
- 回调完成阶段必须使用新的、独立的安全写入时限，不能复用已被上游调用耗尽的请求预算。
- 上游响应体必须有大小上限；解析失败必须按失败处理，不能降级为成功。

### N4 迁移与部署兼容

- 数据库变更必须为增量式，不修改或删除既有业务数据；历史上已识别的迁移 ID 保持可识别。
- 已有部署升级后，原有 OIDC、会话、审计和用户数据继续可用；回滚不得破坏既有数据。
- 新增能力默认关闭；升级后若未配置 Provider，登录页和现有认证行为不发生变化。
- 继续保持单 Rust 二进制 + PostgreSQL + Docker 部署；不引入额外常驻服务、消息队列或微信云开发。
- 开发环境的 Provider 配置和 Secret 不得进入生产默认配置、镜像或仓库。

### N5 Secret 与隐私

- Provider Secret 必须以可逆加密形式存储，主密钥不进入数据库、镜像、日志或前端。
- 主密钥缺失或损坏且存在已加密 Secret 时，服务必须失败关闭，不能以空 Secret 继续运行。
- API、日志、审计摘要、错误信息不得包含 Secret、授权码、访问令牌或完整外部身份标识。
- 只采集登录所需的最小资料：稳定外部标识、必要的展示名/头像、可选的已验证邮箱；不采集好友关系、手机号等无关数据。
- `unionid` 只作为附加信息保存，不用于自动合并或隐式账号关联。

### N6 审计与错误可观测性

- 登录成功、登录失败、用户取消、未绑定拒绝、绑定、解绑、Provider 配置变更、启用/禁用都必须写审计。
- 审计动作和错误码必须稳定、可分类；对外不返回上游原始错误、Secret 或内部堆栈。
- 每次请求返回可追踪的 `request_id`；管理端失败展示 `request_id`，便于排查。
- 统计与审计口径一致，不能把“上游调用发出”表述为“用户已登录”。

### N7 配置完整性与热生效

- 只有启用且配置完整的 Provider 才能出现在公共登录方式列表。
- 配置写入必须具备版本控制，冲突时拒绝并提示刷新；不得静默覆盖。
- 配置修改后无需重启即可生效；已存在的会话不因配置变更被无故撤销。
- 环境变量引导只在配置为空时生效，永不覆盖管理端已保存的 Secret。

### N8 可测试性与 CI 隔离

- 微信、QQ、GitHub 都必须能在不访问真实平台的情况下，通过 fake Provider 完成登录、绑定、解绑、错误和重放测试。
- 集成测试使用一次性 PostgreSQL；不得连接用户业务库或真实第三方账号。
- 数据库测试串行执行；不因并发测试破坏品牌截图或其他共享产物。
- 前端必须通过类型检查、单元测试、lint 和构建；后端必须通过格式、Clippy、单元与关键集成测试。

### N9 性能与故障隔离

- 单个 Provider 超时、限流或故障不得阻塞密码登录、其他 Provider 或 OIDC Token 接口。
- 外部调用必须有全局并发上限；高并发下优先快速失败，不无限排队。
- 正常登录路径不得引入明显的额外数据库事务或全表扫描；统计查询必须可按时间/Provider 限定。
- 现有 OIDC 授权与 Token 路径的延迟目标不因新增社交登录而退化。

### N10 文档与运维

- 提供 GitHub、QQ、微信开放平台的申请条件、回调地址、所需配置和启用步骤。
- 说明 Secret 主密钥的生成、持久化、轮换和丢失后的处理方式。
- 说明未绑定策略、自动建号行为、解绑限制和审计查看方式。
- 提供升级/回滚说明，明确默认关闭、迁移执行时机和回滚边界。
- 明确微信扫码与 QQ 在资质未就绪时的验收方式：代码与 fake 测试完成，真实联调待外部审核。

### N11 外部平台资质门禁

- 微信扫码依赖微信开放平台网站应用；个人主体不可申请，需企业/组织主体和开发者认证。
- QQ 网站应用依赖 ICP 备案域名与 QQ 互联审核；审核未通过时保持禁用。
- 资质未就绪不得阻塞 P6 的代码与自动化验收，但必须在交付说明中标注“真实联调待资质”。
- 不得用非官方手段模拟“检测本机微信登录”；微信 Web 登录只使用官方开放平台扫码。

## 不做的事

- **不做 Yufu 官方微信小程序**：不实现小程序页面、`wx.login`、`code2Session`、`/mini/*`、小程序会话或小程序专用 OIDC 衔接。
- **不做 handoff/resume**：不实现小程序 web-view 与 OIDC 授权事务之间的一次性票据、flow 重绑定或 resume。
- **不做公众号网页 OAuth**：不在微信内置浏览器/微信 PC 客户端内走公众号授权；本阶段只做开放平台扫码。
- **不检测本机微信登录状态**：不提供、也不伪造“检测电脑微信已登录”的能力。
- **不做微信/QQ 的非官方登录方案**：不使用第三方聚合登录、模拟客户端、爬虫或非官方接口。
- **不按邮箱/昵称自动合并账号**：即使邮箱相同且已验证，也不得自动合并。
- **不实现同一 Provider 多身份**：第一阶段每个用户在每个 Provider 下只保留一个身份。
- **不做通用 OIDC 上游 Provider**：Google/Microsoft/企业 IdP 等不在本阶段范围。
- **不做管理员代绑/强制解绑外部身份**：管理员只配置 Provider 和查看审计/统计；账户处置继续使用现有禁用/撤销能力。
- **不做外部账号的专用设密/找回流程**：无密码外部账号如何设置密码不在本阶段；解绑保护会阻止删除最后一个凭据。
- **不做版本 tag 或 GitHub Release**：P6 只交付代码、测试和文档，发布流程另立。
- **不修改 OIDC 核心协议与既有 Client 接入方式**。
- **不引入微信云开发、消息队列或额外常驻服务**。

## 验收标准

### AC1 微信扫码登录

- 配置完整并启用微信 Provider 后，登录页出现微信入口；点击后跳转微信官方扫码页。
- 使用 fake 微信 Provider 完成扫码回调后，已绑定用户获得正常的 Yufu 中心会话，并能继续原有 OIDC 授权流程。
- 未配置或禁用微信时，登录页不展示入口，直接访问发起/回调接口被拒绝。
- 用户取消授权、state 过期、state 重放、code 重放、上游错误时，不建立会话，返回稳定错误并写审计。

### AC2 微信绑定与解绑

- 已登录用户可以从账户中心发起微信绑定并成功保存身份。
- 未登录用户不能完成绑定。
- 同一微信 `openid` 已属于其他用户时，绑定被拒绝，且不泄露对方账户信息。
- 解绑微信后，密码/GitHub/QQ 等其他登录方式仍可用，现有会话不被强制撤销。
- 当微信是唯一登录凭据时，解绑被拒绝。

### AC3 QQ 登录与绑定

- 配置完整并启用 QQ 后，登录页出现 QQ 入口；fake QQ 授权回调可以建立中心会话并继续 OIDC。
- QQ 返回异常 JSON/JSONP、缺少 openid、用户取消、state 重放时，登录失败且不建立会话。
- 已登录用户可以绑定/解绑 QQ；重复绑定与最后凭据保护行为与微信一致。
- QQ 未配置或禁用时，入口不展示，发起/回调失败关闭。

### AC4 未绑定策略

- 默认 `disabled` 下，未绑定第三方身份登录返回稳定错误，不创建 Yufu 用户、不建立会话。
- 切换为 `open` 后，未绑定身份首次登录创建无密码外部账号并建立绑定；该账号不能密码登录，且不具备管理员/开发者权限。
- 两个不同第三方身份使用相同邮箱/昵称时，不会被自动合并到同一 Yufu 用户。
- 并发首次登录不会产生重复账号或重复绑定。

### AC5 Provider 配置与管理

- 管理员可以在控制台配置 GitHub/QQ/微信的 Client ID/AppID 和 Secret，并启用/禁用。
- 任何读取接口、页面、日志和审计摘要都不返回 Secret 明文。
- 配置不完整时不能启用；禁用后登录页入口消失，新发起被拒绝。
- 并发修改发生 revision 冲突时，后写者被拒绝并提示刷新。
- 配置修改后无需重启，登录页与发起接口立即反映新状态。
- 环境变量引导不会覆盖管理端已保存的 Secret。

### AC6 登录统计

- 管理员可以查看最近 24 小时和最近 7 天按 Provider 分组的成功数、失败数和主要失败分类。
- 统计结果不包含 Secret、授权码、访问令牌或完整外部身份标识。
- 统计口径与审计事件一致，失败分类可区分取消、未绑定、上游不可用和状态错误。

### AC7 Provider 隔离与失败关闭

- 单一 Provider 超时/故障时，密码登录、其他 Provider 和 OIDC Token 接口仍可用。
- 未启用 Provider 的旧回调链接不能完成登录。
- 三个 Provider 的登录/绑定/解绑错误分类、审计、限流行为一致。

### AC8 OIDC 无回归

- 既有 OIDC Discovery、授权码 + PKCE、Token、UserInfo、撤销和会话流程的集成测试全部通过。
- 既有 Client 不修改配置即可继续登录；ID Token 的 `sub` 仍是 Yufu 用户标识，不是第三方 openid。
- 新增能力默认关闭时，登录页与现有认证行为无变化。

### AC9 数据库迁移与升级

- 在上一版本数据库快照上执行迁移成功；新表为空或仅含默认禁用的 Provider。
- 迁移回滚不删除既有用户、会话、审计或 OIDC 数据。
- 升级后未配置 Provider 时，服务正常启动且登录行为不变。

### AC10 安全与审计

- state 一次性、浏览器绑定、过期后拒绝；回调地址不可由请求篡改。
- 绑定完成时会话失效或用户不匹配时拒绝绑定。
- Secret 加密存储；主密钥缺失且存在密文时服务拒绝启动。
- 登录、失败、取消、绑定、解绑、配置变更、启用/禁用均有审计记录。
- 日志、错误响应、审计摘要中不出现 Secret、授权码、访问令牌或完整外部标识。

### AC11 测试与构建

- Rust 格式检查、Clippy、单元测试和关键集成测试通过。
- 微信/QQ/GitHub 均有 fake Provider 端到端测试，且 CI 不访问真实第三方。
- 前端类型检查、单元测试、lint 和构建通过。
- 数据库集成测试串行执行，不破坏共享产物。
