本页给两条路径：**用 Docker 起完整栈**（推荐，本机不需要 Rust 与 Node），
或**从源码运行**（需要改代码时用）。两条路径最后都用 Discovery 文档确认协议端点可用。

## 前置要求

用 Docker 只需要：

- Docker Engine 与 Compose v2（`docker compose`）
- 容器可出站访问 `UDP/123`——启动前会校验认证时钟，失败即退出

从源码运行时另需：

- Rust 工具链（使用 workspace 的 edition 与依赖）
- Node.js ≥ 22.23.4 与 pnpm 10+

生产部署需要 HTTPS 与受信 NTP 来源。

## 用 Docker 跑起来（推荐）

镜像发布在 `ghcr.io/bin-hy/yufu`（`linux/amd64` / `linux/arm64`）。整个栈都是官方镜像，
**不需要克隆仓库，也不需要手写配置文件**——镜像首次启动时会根据环境变量生成配置并签发签名私钥。

把下面的内容存成 `compose.yaml`，改掉标注的密码与密钥：

```yaml
services:
  postgres:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: yufu
      POSTGRES_PASSWORD: local-dev-password      # 换掉
      POSTGRES_DB: yufu
    volumes: [yufu-pg:/var/lib/postgresql]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready --username yufu --dbname yufu"]
      interval: 5s
      retries: 12

  yufu:
    image: ghcr.io/bin-hy/yufu:latest
    depends_on:
      postgres: {condition: service_healthy}
    environment:
      YUFU_ISSUER: https://localhost:8443        # 必须是浏览器访问的地址
      YUFU_ADMIN_USERNAME: admin
      YUFU_ADMIN_PASSWORD: change-me-now         # 换掉
      AUTH_SECRET: 6f1c9a2e4b7d8f30a1c2e3b4d5f60718   # 换掉，≥32 字符
      DATABASE_URL: postgres://yufu:local-dev-password@postgres:5432/yufu
    volumes: [yufu-state:/var/lib/yufu]

  caddy:
    image: caddy:2-alpine
    depends_on: [yufu]
    ports: ["8443:8443"]
    command: caddy reverse-proxy --from https://localhost:8443 --to http://yufu:4000

volumes:
  yufu-pg:
  yufu-state:
```

```bash
docker compose up -d
```

打开 `https://localhost:8443`，用 `admin` / `change-me-now` 登录。首次启动会自动执行版本化数据库迁移。
本地试用时 Caddy 用自带的本地 CA 签发证书，浏览器的自签名警告是预期的。

| 环境变量 | 作用 |
| --- | --- |
| `YUFU_ISSUER` | OIDC issuer，必须与浏览器实际访问地址完全一致 |
| `AUTH_SECRET` | 会话与 CSRF 材料密钥，至少 32 字符 |
| `DATABASE_URL` | PostgreSQL 连接串 |
| `YUFU_ADMIN_USERNAME` / `YUFU_ADMIN_PASSWORD` | 首次启动创建的超级管理员 |
| `YUFU_ORIGINS` | 允许的浏览器 origin，默认等于 `YUFU_ISSUER` |
| `PORT` | 容器内监听端口，默认 `4000` |

:::caution
容器内的服务只能监听 `0.0.0.0`，因此**不能**使用 `--allow-insecure-loopback-cookies`，对外入口必须是
HTTPS —— 这就是上面需要 Caddy 的原因。

以上是**评估模式**：配置与签名私钥由镜像生成，私钥留在 `yufu-state` 卷里，重新创建容器不会换钥。
生产环境应当挂载自己的 `/etc/yufu/yufu.toml` 与签名私钥，镜像检测到挂载配置后会完全以它为准，
不会再生成任何东西。做法见[容器部署](/operations/docker/)。
:::

### 只跑服务，不用 Compose

已经有 PostgreSQL 时，一条命令即可：

```bash
docker run -d --name yufu -p 4000:4000 \
  -e YUFU_ISSUER=https://id.example.com \
  -e YUFU_ADMIN_USERNAME=admin -e YUFU_ADMIN_PASSWORD='换成强密码' \
  -e AUTH_SECRET="$(openssl rand -hex 32)" \
  -e DATABASE_URL=postgres://user:pass@db:5432/yufu \
  -v yufu-state:/var/lib/yufu \
  ghcr.io/bin-hy/yufu:latest
```

同样需要在前置一层 HTTPS 终结（反向代理或负载均衡），原因同上。

## 从源码运行

需要改动代码，或想直接用本机工具链调试时走这条路径。

### 1. 获取代码与依赖

```bash
git clone https://github.com/Bin-hy/yufu.git
cd yufu
pnpm install --frozen-lockfile
```

### 2. 启动数据库

`compose.yaml` 只提供鉴权 PostgreSQL，默认映射到本机 `5433`：

```bash
docker compose up -d
```

默认库名为 `yufu`，用户名与密码均为 `postgres`。生产环境必须替换这些凭据。

### 3. 准备配置

```bash
cp conf/yufu.example.toml conf/yufu.local.toml
```

至少确认以下字段：

```toml
[http]
listen = "127.0.0.1:4000"

[auth]
secret = "替换为足够长的随机字符串"

[auth.super_admin]
username = "admin"
password = "替换为强密码"

[oidc]
issuer = "http://127.0.0.1:4000"
rsa_private_key_path = "conf/oidc_rsa_private.local.pem"

[database]
url = "postgres://postgres:postgres@localhost:5433/yufu"

[security_clock]
servers = ["time.apple.com:123", "time.cloudflare.com:123"]
min_agreeing_sources = 2
```

:::caution
`--allow-insecure-loopback-cookies` 只适用于本机 HTTP。它要求监听地址与 issuer 都是 loopback；
生产环境必须使用 HTTPS 和默认的 Secure Cookie。
:::

### 4. 启动服务

```bash
pnpm build:web
cargo run --bin yufu --features webui -- \
  --config conf/yufu.local.toml \
  --allow-insecure-loopback-cookies
```

`--features webui` 会嵌入 `assets/web` 的前端产物，因此首次运行前需要执行 `pnpm build:web`。
启动时会自动执行版本化数据库迁移。

### 5. 首次登录

浏览器打开：

```text
http://127.0.0.1:4000
```

使用 `[auth.super_admin]` 中的账号登录。登录后可进入：

- `/account`：账户资料；`/account/apps`：可访问应用；`/account/consents`：资料授权；`/account/sessions`：登录会话
- `/developer/*`：本人应用的注册、配置、版本与审批
- `/admin/*`：账户、应用、组、分配、审批与审计

侧栏入口按账户资格显示：普通成员使用账户中心，开发者资格开放开发者控制台，企业管理员可进入企业管理。
工作台位于 `/dashboard`。各页面截图与操作说明见[控制台使用指南](/guides/console/)。

### 6. 验证 Discovery

```bash
curl -s http://127.0.0.1:4000/.well-known/openid-configuration | jq .
curl -s http://127.0.0.1:4000/.well-known/jwks.json | jq .
```

健康检查：

```bash
curl -s http://127.0.0.1:4000/api/v1/health/ready | jq .
```

响应中的 `security_clock_synchronized` 为 `true` 才表示认证时钟就绪。时钟异常时认证入口返回 503。
