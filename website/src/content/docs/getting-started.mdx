本页给两条路径：**用 Docker 起完整栈**（推荐，本机不需要 Rust 与 Node），
或**从源码运行**（需要改代码时用）。两条路径最后都用 Discovery 文档确认协议端点可用。

## 前置要求

用 Docker 只需要：

- Docker Engine 与 Compose v2（`docker compose`）
- 容器可出站访问 `UDP/123`——启动前会校验认证时钟，失败即退出

从源码运行时另需：

- Rust 工具链（使用 workspace 的 edition 与依赖）
- Node.js ≥ 22.23.4 与 pnpm 10+

生产部署需要 HTTPS 与受信 NTP 来源。

## 用 Docker 跑起来（推荐）

仓库发布 `linux/amd64` 与 `linux/arm64` 镜像，可以跳过本机的 Rust 与 Node 安装。
自带的 Compose 栈由 Caddy 终止 TLS、身份服务从 `ghcr.io` 拉取、PostgreSQL 只在内部网络，
数据库不暴露任何宿主机端口。

```bash
git clone https://github.com/Bin-hy/yufu.git
cd yufu/deploy/docker

cp env.example .env
cp yufu.toml.example yufu.toml
mkdir -p state
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
  -out state/oidc_rsa_private.pem
chmod 600 state/oidc_rsa_private.pem
```

`.env` 里带 `CHANGE_ME` 的值都要替换，至少 `POSTGRES_PASSWORD` 与 `AUTH_SECRET`；
再把镜像指向已发布版本，省掉容器内的编译：

```dotenv
YUFU_DOMAIN=localhost
YUFU_HTTPS_PORT=8443
YUFU_IMAGE=ghcr.io/bin-hy/yufu:latest
```

`issuer` 与 `[auth].origins` 必须写成浏览器实际访问的地址，两处要完全一致，
否则登录后跳转或接口会因 Origin 校验失败被拒：

```toml
[auth]
origins = ["https://localhost:8443"]

[oidc]
issuer = "https://localhost:8443"
```

拉取镜像并启动：

```bash
docker compose pull yufu
docker compose up -d --no-build
docker compose ps
```

打开 `https://localhost:8443`，用 `[auth.super_admin]` 中的账号登录。首次启动会自动执行版本化数据库迁移。

:::caution
容器内的服务只能监听 `0.0.0.0`，因此**不能**使用 `--allow-insecure-loopback-cookies`，对外入口必须是 HTTPS。
本地试用时 Caddy 会用本地 CA 签发证书，浏览器会提示自签名。
`state/oidc_rsa_private.pem` 必须持久保留，换钥会让已签发的令牌与既有客户端校验失效。
:::

域名、证书、备份、升级与故障排查见[容器部署](/operations/docker/)。

## 从源码运行

需要改动代码，或想直接用本机工具链调试时走这条路径。

### 1. 获取代码与依赖

```bash
git clone https://github.com/Bin-hy/yufu.git
cd yufu
pnpm install --frozen-lockfile
```

### 2. 启动数据库

`compose.yaml` 只提供鉴权 PostgreSQL，默认映射到本机 `5433`：

```bash
docker compose up -d
```

默认库名为 `yufu`，用户名与密码均为 `postgres`。生产环境必须替换这些凭据。

### 3. 准备配置

```bash
cp conf/yufu.example.toml conf/yufu.local.toml
```

至少确认以下字段：

```toml
[http]
listen = "127.0.0.1:4000"

[auth]
secret = "替换为足够长的随机字符串"

[auth.super_admin]
username = "admin"
password = "替换为强密码"

[oidc]
issuer = "http://127.0.0.1:4000"
rsa_private_key_path = "conf/oidc_rsa_private.local.pem"

[database]
url = "postgres://postgres:postgres@localhost:5433/yufu"

[security_clock]
servers = ["time.apple.com:123", "time.cloudflare.com:123"]
min_agreeing_sources = 2
```

:::caution
`--allow-insecure-loopback-cookies` 只适用于本机 HTTP。它要求监听地址与 issuer 都是 loopback；
生产环境必须使用 HTTPS 和默认的 Secure Cookie。
:::

### 4. 启动服务

```bash
pnpm build:web
cargo run --bin yufu --features webui -- \
  --config conf/yufu.local.toml \
  --allow-insecure-loopback-cookies
```

`--features webui` 会嵌入 `assets/web` 的前端产物，因此首次运行前需要执行 `pnpm build:web`。
启动时会自动执行版本化数据库迁移。

### 5. 首次登录

浏览器打开：

```text
http://127.0.0.1:4000
```

使用 `[auth.super_admin]` 中的账号登录。登录后可进入：

- `/account`：账户资料；`/account/apps`：可访问应用；`/account/consents`：资料授权；`/account/sessions`：登录会话
- `/developer/*`：本人应用的注册、配置、版本与审批
- `/admin/*`：账户、应用、组、分配、审批与审计

侧栏入口按账户资格显示：普通成员使用账户中心，开发者资格开放开发者控制台，企业管理员可进入企业管理。
工作台位于 `/dashboard`。各页面截图与操作说明见[控制台使用指南](/guides/console/)。

### 6. 验证 Discovery

```bash
curl -s http://127.0.0.1:4000/.well-known/openid-configuration | jq .
curl -s http://127.0.0.1:4000/.well-known/jwks.json | jq .
```

健康检查：

```bash
curl -s http://127.0.0.1:4000/api/v1/health/ready | jq .
```

响应中的 `security_clock_synchronized` 为 `true` 才表示认证时钟就绪。时钟异常时认证入口返回 503。
