## Choose a delivery method

| | Container image | Binary + systemd |
| --- | --- | --- |
| Start | one `docker compose up` | needs a Rust and Node build |
| TLS | Caddy issues and renews certificates | you bring the reverse proxy |
| Upgrade | pull a new image and recreate | replace the binary and restart |
| Fits | single-host self-hosting, internal identity centre | existing host operations with fine control |

Images are published at `ghcr.io/bin-hy/yufu` (`linux/amd64` and `linux/arm64`); the full stack adds
PostgreSQL and a Caddy TLS entry point, covered in [container deployment](/en/operations/docker/).
The rest of this page describes the binary delivery.

## Production configuration

- `oidc.issuer` must be the public HTTPS base URL and must match the browser-facing origin exactly.
- `auth.secret` must be a long random value, unique per environment.
- `oidc.rsa_private_key_path` must point at a persistent key; production never generates one.
- Never enable `--allow-insecure-loopback-cookies`.
- `security_clock.servers` must use trusted NTP sources.
- Use a dedicated database account with a strong password and restricted network access.

## Binary delivery

### Build

```bash
pnpm install --frozen-lockfile
pnpm build:web
cargo build --bin yufu --features webui --release
```

The artifact is a single binary at `target/release/yufu` with the frontend embedded. Deployment
needs only the binary, configuration, RSA private key, and database.

### systemd

File locations follow the `conf/yufu.service` template shipped in the packages:

```ini
[Unit]
Description=yufu · enterprise identity and SSO service
Requires=network-online.target
After=network-online.target

[Service]
Type=simple
DynamicUser=yes
ExecStart=/usr/bin/yufu --config /etc/yufu/yufu.toml
WorkingDirectory=/var/lib/yufu
StateDirectory=yufu
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

```bash
sudo install -m 0755 yufu /usr/bin/yufu
sudo install -d -m 0755 /etc/yufu
# Install an edited configuration, never enable the example as-is
sudo install -m 0640 yufu.toml /etc/yufu/yufu.toml
sudo install -m 0644 yufu.service /etc/systemd/system/yufu.service
sudo systemctl daemon-reload
sudo systemctl enable --now yufu
sudo systemctl status yufu
```

The unit runs with `DynamicUser=yes`, so there is no fixed account or UID: grant read access to the
configuration through a supplementary group (for example `SupplementaryGroups=` in a drop-in) or an
ACL. Keep the signing key under `/var/lib/yufu/`, which `StateDirectory=yufu` manages. The
Windows and macOS packages only ship a manually run executable with no service registration.

## Reverse proxy

```nginx
server {
    listen 443 ssl http2;
    server_name id.example.com;

    ssl_certificate     /etc/ssl/id.example.com.pem;
    ssl_certificate_key /etc/ssl/id.example.com.key;

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

The proxy must preserve the original `Host` and scheme, or cookie and Origin validation will fail.

## Health check

```bash
curl -fsS https://id.example.com/api/v1/health/ready
```

Only route traffic when it returns 200 with `security_clock_synchronized=true`. A 503 during clock
failure is expected; do not bypass it with retries.

## Upgrade

1. Back up the database and the RSA private key.
2. Build the new binary and frontend.
3. Stop the service and replace the binary.
4. Start the service; versioned migrations run automatically.
5. Verify discovery, the health check, and one real login.

## Rollback boundaries

Migrations are versioned. Before rolling back a binary, confirm the new version did not run an
irreversible migration. Historical data, registered clients, and grants are never deleted
automatically, and a rollback does not restore revoked sessions.

## Pitfalls

A containerised service can only listen on `0.0.0.0`, so container deployments **cannot** use
`--allow-insecure-loopback-cookies`; the public entry point must be HTTPS. A reverse proxy must
preserve the original `Host` and set `X-Forwarded-Proto: https`, otherwise both the cookie and the
origin check fail.
