This page takes the shortest path to a running yufu: start the database, write a configuration,
run the service, sign in to the admin console, and confirm the protocol endpoints through discovery.

## Requirements

- A Rust toolchain (matching the workspace edition and dependencies)
- Node.js ≥ 22.23.4 and pnpm 10+
- A Docker-compatible container runtime for PostgreSQL
- HTTPS and trusted NTP sources for production

## 1. Get the code and dependencies

```bash
git clone https://github.com/Bin-hy/yufu.git
cd yufu
pnpm install --frozen-lockfile
```

## 2. Start the database

`compose.yaml` only provides the identity PostgreSQL instance, mapped to local port `5433`:

```bash
docker compose up -d
```

The default database is `yufu`, with `postgres` as both user and password.
Replace these credentials in production.

## 3. Prepare the configuration

```bash
cp conf/yufu.example.toml conf/yufu.local.toml
```

At minimum, review these fields:

```toml
[http]
listen = "127.0.0.1:4000"

[auth]
secret = "replace with a long random value"

[auth.super_admin]
username = "admin"
password = "replace with a strong password"

[oidc]
issuer = "http://127.0.0.1:4000"
rsa_private_key_path = "conf/oidc_rsa_private.local.pem"

[database]
url = "postgres://postgres:postgres@localhost:5433/yufu"

[security_clock]
servers = ["time.apple.com:123", "time.cloudflare.com:123"]
min_agreeing_sources = 2
```

:::caution
`--allow-insecure-loopback-cookies` is for local HTTP only. It requires both the listener and the
issuer to be loopback. Production must use HTTPS and the default secure cookies.
:::

## 4. Start the service

```bash
pnpm build:web
cargo run --bin yufu --features webui -- \
  --config conf/yufu.local.toml \
  --allow-insecure-loopback-cookies
```

`--features webui` embeds the frontend build from `assets/web`, so run `pnpm build:web`
first. Versioned database migrations run automatically at startup.

## 5. Sign in for the first time

Open:

```text
http://127.0.0.1:4000
```

Sign in with the account from `[auth.super_admin]`. After signing in you can reach:

- `/account`: profile; `/account/apps`: accessible applications; `/account/consents`: data consent; `/account/sessions`: login sessions
- `/developer/*`: registration, configuration, versions, and approvals for your applications
- `/admin/*`: accounts, applications, groups, assignments, approvals, and audit

Navigation follows account qualifications: all members have the account center, qualified developers
have the developer console, and enterprise administrators have enterprise administration.
The workspace is at `/dashboard`. See the [console guide](/en/guides/console/) for screenshots and workflows.

## 6. Verify discovery

```bash
curl -s http://127.0.0.1:4000/.well-known/openid-configuration | jq .
curl -s http://127.0.0.1:4000/.well-known/jwks.json | jq .
```

Health check:

```bash
curl -s http://127.0.0.1:4000/api/v1/health/ready | jq .
```

Authentication is ready only when `security_clock_synchronized` is `true`. When the clock check fails,
authentication endpoints return 503.
