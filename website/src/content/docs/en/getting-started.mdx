This page offers two paths: **run the full stack with Docker** (recommended — no local Rust or Node
toolchain), or **run it from source** when you need to change code. Both end with the same discovery check.

## Requirements

With Docker you only need:

- Docker Engine with Compose v2 (`docker compose`)
- Outbound `UDP/123` from the container — the security clock is verified at startup and the service exits if it fails

Running from source additionally needs:

- A Rust toolchain (matching the workspace edition and dependencies)
- Node.js ≥ 22.23.4 and pnpm 10+

Production needs HTTPS and trusted NTP sources.

## Run it with Docker (recommended)

Images are published at `ghcr.io/bin-hy/yufu` (`linux/amd64` and `linux/arm64`). Every service in the
stack is an official image, and **you do not clone the repository or write a configuration file** —
on first start the image renders its configuration from environment variables and issues its own
signing key.

Save this as `compose.yaml` and replace the marked password and secret:

```yaml
services:
  postgres:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: yufu
      POSTGRES_PASSWORD: local-dev-password      # replace
      POSTGRES_DB: yufu
    volumes: [yufu-pg:/var/lib/postgresql]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready --username yufu --dbname yufu"]
      interval: 5s
      retries: 12

  yufu:
    image: ghcr.io/bin-hy/yufu:latest
    depends_on:
      postgres: {condition: service_healthy}
    environment:
      YUFU_ISSUER: https://localhost:8443        # must be the browser-facing origin
      YUFU_ADMIN_USERNAME: admin
      YUFU_ADMIN_PASSWORD: change-me-now         # replace
      AUTH_SECRET: 6f1c9a2e4b7d8f30a1c2e3b4d5f60718   # replace, >= 32 chars
      DATABASE_URL: postgres://yufu:local-dev-password@postgres:5432/yufu
    volumes: [yufu-state:/var/lib/yufu]

  caddy:
    image: caddy:2-alpine
    depends_on: [yufu]
    ports: ["8443:8443"]
    command: caddy reverse-proxy --from https://localhost:8443 --to http://yufu:4000

volumes:
  yufu-pg:
  yufu-state:
```

```bash
docker compose up -d
```

Open `https://localhost:8443` and sign in as `admin` / `change-me-now`. Versioned database migrations
run on first start. Caddy signs a certificate with its own local CA, so the browser's self-signed
warning is expected for a local trial.

| Variable | Purpose |
| --- | --- |
| `YUFU_ISSUER` | OIDC issuer; must match the browser-facing origin exactly |
| `AUTH_SECRET` | Session and CSRF material, at least 32 characters |
| `DATABASE_URL` | PostgreSQL connection string |
| `YUFU_ADMIN_USERNAME` / `YUFU_ADMIN_PASSWORD` | Super administrator created on first start |
| `YUFU_ORIGINS` | Allowed browser origins; defaults to `YUFU_ISSUER` |
| `PORT` | Listen port inside the container, default `4000` |

:::caution
Inside a container the service can only listen on `0.0.0.0`, so `--allow-insecure-loopback-cookies`
is unusable and the public entry point must be HTTPS — that is why Caddy is in the stack.

This is **evaluation mode**: the image generates the configuration and the signing key, and the key
lives in the `yufu-state` volume so recreating the container does not rotate it. Production should
mount its own `/etc/yufu/yufu.toml` and signing key; when a configuration is mounted the image uses it
verbatim and generates nothing. See [container deployment](/en/operations/docker/).
:::

### Run the service without Compose

If you already have PostgreSQL, one command is enough:

```bash
docker run -d --name yufu -p 4000:4000 \
  -e YUFU_ISSUER=https://id.example.com \
  -e YUFU_ADMIN_USERNAME=admin -e YUFU_ADMIN_PASSWORD='use-a-strong-one' \
  -e AUTH_SECRET="$(openssl rand -hex 32)" \
  -e DATABASE_URL=postgres://user:pass@db:5432/yufu \
  -v yufu-state:/var/lib/yufu \
  ghcr.io/bin-hy/yufu:latest
```

It still needs HTTPS terminated in front of it, for the reason above.

## Run it from source

Take this path when you need to change code or want to debug with a local toolchain.

### 1. Get the code and dependencies

```bash
git clone https://github.com/Bin-hy/yufu.git
cd yufu
pnpm install --frozen-lockfile
```

### 2. Start the database

`compose.yaml` only provides the identity PostgreSQL instance, mapped to local port `5433`:

```bash
docker compose up -d
```

The default database is `yufu`, with `postgres` as both user and password.
Replace these credentials in production.

### 3. Prepare the configuration

```bash
cp conf/yufu.example.toml conf/yufu.local.toml
```

At minimum, review these fields:

```toml
[http]
listen = "127.0.0.1:4000"

[auth]
secret = "replace with a long random value"

[auth.super_admin]
username = "admin"
password = "replace with a strong password"

[oidc]
issuer = "http://127.0.0.1:4000"
rsa_private_key_path = "conf/oidc_rsa_private.local.pem"

[database]
url = "postgres://postgres:postgres@localhost:5433/yufu"

[security_clock]
servers = ["time.apple.com:123", "time.cloudflare.com:123"]
min_agreeing_sources = 2
```

:::caution
`--allow-insecure-loopback-cookies` is for local HTTP only. It requires both the listener and the
issuer to be loopback. Production must use HTTPS and the default secure cookies.
:::

### 4. Start the service

```bash
pnpm build:web
cargo run --bin yufu --features webui -- \
  --config conf/yufu.local.toml \
  --allow-insecure-loopback-cookies
```

`--features webui` embeds the frontend build from `assets/web`, so run `pnpm build:web`
first. Versioned database migrations run automatically at startup.

### 5. Sign in for the first time

Open:

```text
http://127.0.0.1:4000
```

Sign in with the account from `[auth.super_admin]`. After signing in you can reach:

- `/account`: profile; `/account/apps`: accessible applications; `/account/consents`: data consent; `/account/sessions`: login sessions
- `/developer/*`: registration, configuration, versions, and approvals for your applications
- `/admin/*`: accounts, applications, groups, assignments, approvals, and audit

Navigation follows account qualifications: all members have the account center, qualified developers
have the developer console, and enterprise administrators have enterprise administration.
The workspace is at `/dashboard`. See the [console guide](/en/guides/console/) for screenshots and workflows.

### 6. Verify discovery

```bash
curl -s http://127.0.0.1:4000/.well-known/openid-configuration | jq .
curl -s http://127.0.0.1:4000/.well-known/jwks.json | jq .
```

Health check:

```bash
curl -s http://127.0.0.1:4000/api/v1/health/ready | jq .
```

Authentication is ready only when `security_clock_synchronized` is `true`. When the clock check fails,
authentication endpoints return 503.
