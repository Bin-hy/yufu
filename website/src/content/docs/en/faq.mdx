## After logout, signing in again skips the identity provider

The application cleared only its local session and never ended the central browser session.
RP-initiated logout must use the `end_session_endpoint` from discovery with `id_token_hint` and a
registered `post_logout_redirect_uri`.

For example, Outline needs:

```dotenv
OIDC_LOGOUT_URI=https://id.example.com/oidc/end-session
```

Without it, logout only redirects to the app home page and the central session stays valid.

## The authorization request is rejected with a redirect mismatch

Redirect URIs must match the registered value character by character, including scheme, host, port,
path, and trailing slash. `http://localhost:3000` and `http://localhost:3000/` are different values.

## Every protected API call returns 401

Check the access-token `aud` first. It is the application environment's access audience
(for example `urn:app:production`), not the OIDC client id. Also confirm `typ=at+jwt`; ID Tokens
cannot be used as access tokens.

## Browser requests return 403 with an origin rejection

Cross-site requests carrying `Origin` must match a registered SPA origin exactly. Check scheme, host,
and port, and confirm the preflight method and headers are allowed.

## Login returns 503 and readiness is false

The authentication clock failed its check. Verify reachability and agreement of
`security_clock.servers`, with at least `min_agreeing_sources` fresh samples. Do not disable the check.

## Cookies do not work in production

Production requires HTTPS and the default secure cookies. `--allow-insecure-loopback-cookies` only
permits loopback addresses and cannot be used for a public domain.

## How do I reset the super administrator password

Update `[auth.super_admin]` and restart. Existing account records are not overwritten automatically;
follow your deployment's account governance process to synchronize them.

## Is multi-tenancy, SAML, LDAP, SCIM, or MFA supported

No. cobotusr ships as a single-tenant deployment and explicitly excludes multi-tenancy, external IdP
federation, SAML/LDAP/SCIM, and strong authentication. Integrators must not depend on them.

## Where can I see audit records

Administrators can review them in the audit pages under `/admin/*`. Every administrative write records
the actor, target, and result.
