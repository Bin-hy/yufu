---
title: Configuration
description: Configuration keys, defaults, and command-line flags.
---

Configuration is TOML, passed with `--config <path>`; without it the service reads `yufu.toml`
from the working directory. Omitted fields use their defaults.

## Command-line flags

| Flag | Description |
| --- | --- |
| `-c, --config <path>` | Path to the configuration file; defaults to `yufu.toml` |
| `-v` / `-vv` / `-vvv` | Log level info / debug / trace |
| `--allow-insecure-loopback-cookies` | Local HTTP development mode; listener and issuer must be loopback |
| `--check-security-clock` | Diagnose the authentication clock without opening the database or HTTP server |

## `[http]`

| Key | Default | Description |
| --- | --- | --- |
| `listen` | `0.0.0.0:4000` (overridable by `PORT`) | HTTP listen address |
| `public` | empty | Public base URL; used to derive the issuer when `oidc.issuer` is empty |
| `api_prefix` | `/api/v1` | Management API prefix |

## `[auth]`

| Key | Default | Description |
| --- | --- | --- |
| `secret` | built-in default | JWT / CSRF signing secret; replace in production |
| `tokens` | `[]` | Static debug tokens for local troubleshooting only |
| `exp_seconds` | `7200` | Legacy JWT access-token lifetime; does not control console SSO |
| `refresh_exp_seconds` | `604800` | Refresh-token lifetime in seconds |
| `origins` | local development origins | Allowed CORS origins |
| `allow_insecure_loopback_cookies` | `false` | Equivalent to the CLI flag |
| `rsa_private_key_path` | `conf/oidc_rsa_private.local.pem` | Compatibility field; the `[oidc]` value wins |

### `[auth.super_admin]`

| Key | Description |
| --- | --- |
| `username` | Super administrator username |
| `password` | Super administrator password |

### `[[auth.accounts]]`

Repeatable static account entries with the same `username` and `password` fields.

## `[identity]`

The console uses a server-side SSO session and an HttpOnly cookie, separately from legacy JWTs and application access tokens.

| Field | Default | Meaning |
| --- | --- | --- |
| `sso_session_ttl_seconds` | `43200` | Console session lifetime: 12 hours; allowed range 1–43200 seconds |
| `access_token_ttl_seconds` | `300` | Managed OIDC access-token lifetime; does not set the console login lifetime |

The SSO deadline is fixed at password authentication and does not slide when browsing. Changes apply to newly created sessions. `auth.exp_seconds` and legacy refresh-token settings do not extend this session. A failed identity check due to a temporary service/network problem is retried separately; a confirmed 401 requires signing in again.

## `[oidc]`

| Key | Default | Description |
| --- | --- | --- |
| `issuer` | derived from `http.public` or `http.listen` | Public issuer; HTTPS in production |
| `rsa_private_key_path` | `conf/oidc_rsa_private.local.pem` | RS256 signing key path |
| `access_token_expire_seconds` | follows `auth.exp_seconds` | Legacy OIDC access-token lifetime |
| `refresh_token_expire_seconds` | follows `auth.refresh_exp_seconds` | Refresh-token lifetime |
| `email_domain` | `yufu.local` | Domain used by UserInfo when a user has no email |
| `signing_algorithm` | `RS256` | `RS256`, or `HS256` for tests |
| `mcp_token_max_ttl_days` | `90` | Maximum lifetime for long-lived MCP tokens |

### `[[oidc.bootstrap_clients]]`

Clients registered at startup. Existing `client_id` entries are never overwritten and secrets are
never silently rotated by configuration.

```toml
[[oidc.bootstrap_clients]]
client_id = "example-spa"
name = "Example application"
redirect_uris = ["http://localhost:5174/oauth/callback"]
allowed_scopes = ["openid", "profile", "email"]
grant_types = ["authorization_code", "refresh_token"]
public_client = true
```

## `[database]`

| Key | Default | Description |
| --- | --- | --- |
| `url` | `DATABASE_URL` or local PostgreSQL | Connection string |
| `max_connections` | `10` | Connection pool limit |
| `connect_timeout` | `30` | Connect timeout in seconds |

## `[security_clock]`

Authentication endpoints only serve requests while the clock is healthy. Checks measure host time
and never modify the system clock.

| Key | Default | Description |
| --- | --- | --- |
| `servers` | Apple / Cloudflare / Aliyun NTP | Trusted time sources |
| `min_agreeing_sources` | `2` | Minimum number of agreeing sources |
| `poll_interval_seconds` | `10` | Poll interval |
| `sample_ttl_seconds` | `30` | Sample lifetime |
| `timeout_millis` | `1500` | Per-query timeout |

:::caution
Plain NTP has no transport authentication. Production should use NTP sources inside a trusted
network, or inject a clock with trusted health evidence from the host. Do not substitute public
sources for a deployment trust policy.
:::

## `[log]`

| Key | Default | Description |
| --- | --- | --- |
| `level` | `info` | `off` / `error` / `warn` / `info` / `debug` / `trace`; overridable by `LOG_LEVEL` |

## Environment variables

| Variable | Effect |
| --- | --- |
| `DATABASE_URL` | Default for `[database].url` |
| `PORT` | Default port for `[http].listen` |
| `LOG_LEVEL` | Log level |
| `AUTH_SECRET` | Default for `[auth].secret`; replace in production |

Environment variables apply only when the configuration file omits the field. An explicit
`[database].url` or `[auth].secret` wins. Container deployments rely on this to keep credentials in
`.env` instead of the configuration file.
